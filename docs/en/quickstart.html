Quickstart

Install localmelo, run a first task on your own model server, save a configuration and start the gateway.

Before you begin

  • macOS (developed and tested) or Linux (should work, untested); Windows is not supported.
  • Python 3.11 or later, Git, and uv (or pip, see Install with pip).
  • A model server. The commands below use Ollama with ollama pull qwen3:8b.
  • On a Mac with Apple silicon, oMLX is recommended: use http://127.0.0.1:8000/v1 and your model's folder name instead.
  • Any OpenAI-compatible server works too: use its /v1 URL and its model name.

Install

git clone https://github.com/localmelo/localmelo.git
cd localmelo
uv sync --extra gateway
source .venv/bin/activate
  • uv creates .venv/ (installing Python 3.13 if needed) with the gateway's dependencies.
  • Keep the folder name localmelo: a renamed folder or a ZIP download fails with ModuleNotFoundError: No module named 'localmelo'.
  • Activation lasts for this terminal; elsewhere use uv run --project <clone> melo ….
  • On a Mac with Apple silicon, uv run python scripts/build_macos_app.py --install builds the app into ~/Applications.

Install with pip

git clone https://github.com/localmelo/localmelo.git
cd localmelo
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[gateway]"

python3 must be Python 3.11 or later; -e keeps the install linked to this checkout.

Run your first task

The model can run shell commands and Python code, and read or write any file you can: there is no sandbox. To run a task without tools, add --builtins none. See the security policy.

melo -u http://127.0.0.1:11434/v1 -m qwen3:8b "What is 6*7?"

With oMLX, use its URL and a model folder's name:

melo -u http://127.0.0.1:8000/v1 -m Qwen3-8B-4bit "What is 6*7?"
  • The answer prints on stdout, and the exit code is 0 (echo $? prints 0).
  • -u (--url) picks the server for this run, without a config file; -m (--model) names the model.
  • It sends no API key: for a cloud API, save a configuration (below).
  • Every option is in the command-line reference.

Get the result as JSON

melo -u http://127.0.0.1:11434/v1 -m qwen3:8b -o json "What is 6*7?"
  • stdout holds exactly one JSON line; the exit code is 0 only when status is completed.

Run results

  • status says how the run ended, such as completed, budget_exhausted or provider_error.
  • The counters give the steps, model requests and tool calls; config records the options.
  • Run results lists every status and field.

Save a configuration

Run melo in a terminal. With nothing saved, it finds a model server on this computer, asks to use it, and saves ~/.cache/localmelo/config.toml:

$ melo
melo uses a model server on this computer (oMLX, Ollama, LM Studio…).
Found a model server at http://127.0.0.1:11434/v1 (1 model).
✓ http://127.0.0.1:11434/v1 lists 1 model; using qwen3:8b.
melo remembers across chats by words only; melo setup adds search by meaning.
Saved to ~/.cache/localmelo/config.toml (melo setup changes it).
melo 0.1.0 · qwen3:8b (/model to change)
~/demo-project
Try: What is this project? · / commands · ctrl+d quit
  • From then on, melo and melo "<task>" use the saved server.
  • Every question is a list: ↑ ↓ move, Enter confirms, Esc takes the safe answer.
  • With no server running, melo prints the commands that start one and offers Check again.
  • First run and Set up an embedding model have the details.

With the setup wizard

The wizard also sets up an embedding server or a cloud API. For a cloud API, first run export OPENAI_API_KEY="<your key>" (or your vendor's variable).

melo setup
melo serve
PromptWhat to enter
Use this model server?The server it found, or Use another server for the full menu.
Chat backendYour server type, such as 2. Ollama (local endpoint), or a cloud vendor.
Base URLYour server's URL; Enter keeps the default in brackets. Ollama's has no /v1.
Chat model nameThe model, such as qwen3:8b.
Embedding backend5. None (no long-term memory), or an embedding model the chat server lists.
  • The wizard sends a short test request to each server before it saves.
  • If the check fails, choose Try again, Save anyway or Cancel setup.
  • On success it prints Config saved to …; then melo serve starts the gateway on http://127.0.0.1:8401.

Set up an embedding model

Long-term memory needs an embedding model that your server already serves. With Ollama:

ollama pull qwen3-embedding:0.6b
curl -sS http://127.0.0.1:11434/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model": "qwen3-embedding:0.6b", "input": "ping"}'
melo setup    # Embedding backend: 2 (Ollama); URL http://localhost:11434; model qwen3-embedding:0.6b

With oMLX the chat server also serves the model:

curl -sS http://127.0.0.1:8000/v1/models
curl -sS http://127.0.0.1:8000/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model": "Qwen3-Embedding-0.6B", "input": "ping"}'
  • The reply must hold a non-empty data[0].embedding.
  • For oMLX, set embedding_backend = "vllm" with embedding_url and embedding_model (oMLX).
  • A new model means new vectors: old entries stop ranking until you remove ~/.cache/localmelo/memory/long_term.db*.
  • The guide covers Ollama, oMLX, vLLM, SGLang and MLC.

Start the gateway

Run melo serve. From a second terminal, check it and run a task through it; the token goes to curl through a pipe, not the command line:

{ printf 'Authorization: Bearer '; cat ~/.cache/localmelo/gateway/auth/token; printf '\n'; } | curl -H @- http://127.0.0.1:8401/v1/health
{ printf 'Authorization: Bearer '; cat ~/.cache/localmelo/gateway/auth/token; printf '\n'; } | curl -H @- -X POST http://127.0.0.1:8401/v1/agent/run \
  -H "Content-Type: application/json" \
  -d '{"query": "What is 6*7?"}'

Example output (values vary):

{"status":"ok","uptime":12.3,"sessions":{"active":0,"busy":0,"max":50},"chat_backend":"ollama","embedding_backend":"none"}
{"result":"42","session_id":"a7e8f646ca2e"}
  • The health check does not contact the model server; a task does.
  • At a terminal on this computer, melo serve opens the console in your browser; melo console opens it again.
  • Over SSH, melo console prints a one-use link to open within 60 seconds; do not share it.
  • Ctrl+C stops the gateway; melo "What is 6*7?" then uses the saved configuration.
  • melo-task creates and controls the gateway's tasks.

Interactive conversations

melo
# Or talk to an OpenAI-compatible server that is not saved. Without
# -m it uses the server's only chat model or its one loaded model;
# with several chat models and not exactly one loaded, it exits 2 and lists them:
melo -u http://127.0.0.1:8000/v1
melo -u http://127.0.0.1:8000/v1 -m YOUR_MODEL_ID
  • Each tool call shows on one line, and the answer prints as Markdown; developer mode adds the step, the phase and the run's progress facts.
  • Type / for commands: /help, /model, /status, /attach PATH, /new; Ctrl+D leaves.
  • melo asks before a shell command, Python code or a file write: allow once, allow for the session, or refuse and say why.
  • melo works in the current folder (-w DIR picks another); Esc stops a turn.
  • The interactive UI has the keys and the rest.
  • The console at http://127.0.0.1:8401/ uses the gateway's model; Settings or melo setup change it.
  • On a first run, its welcome finds the model server on this Mac and connects it with Use this model.
  • Chats are saved in the gateway's sessions.db, so a restart keeps them.
  • Approval cards show the diff a file write makes; they are not a security boundary against same-user processes.

Serve a model with oMLX

oMLX serves MLX models through an OpenAI-compatible API on a Mac with Apple silicon and macOS 15 or later.

  1. Install oMLX with Homebrew (the oMLX app also installs ~/.omlx/bin/omlx):

    brew tap jundot/omlx https://github.com/jundot/omlx
brew install jundot/omlx/omlx

  2. Put each model in its own folder; the folder's name is the model id:

    hf download mlx-community/Qwen3-8B-4bit --local-dir ~/models/Qwen3-8B-4bit

  3. Start the server, and leave it running in its own terminal:

    omlx serve --model-dir ~/models --port 8000

    Do not set --api-key: localmelo sends no key to a local server. On HTTP 401, turn on Allow inference without API key in oMLX's admin page.

  4. Check that the server lists the model ("id": "Qwen3-8B-4bit"):

    curl -sS http://127.0.0.1:8000/v1/models

  5. Run a task with that id (a first request loads the model; -X request_timeout_s=600 gives it more time):

    melo -u http://127.0.0.1:8000/v1 -m Qwen3-8B-4bit "What is 6*7?"
  • To make oMLX your default, run melo before anything is saved: it finds oMLX on port 8000 and saves the model you pick.
  • One chat model is the default; with several, setup marks the loaded ones and picks the first.
  • When none is loaded, nothing is picked for you: loading a large model can take minutes.
  • The guide has the config file and how to turn off a Qwen3 model's thinking.
