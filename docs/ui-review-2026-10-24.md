## Changes

The web interface now uses a restrained workspace layout with a searchable chat
sidebar, readable assistant responses, a bottom composer, a model connection
dialog, and a mobile navigation drawer. HTML, CSS, and JavaScript are packaged
as local assets without CDN dependencies.

Behavior fixes include:

- Refresh recovery and polling between browser clients connected to one gateway.
- Per-chat/per-tab drafts; failed requests retain the draft without overwriting
  newer text. No prompt is sent automatically when creating a chat.
- Actual harness cancellation, busy-session conflict handling, and visible
  deletion, discovery, and connection errors.
- Safe Markdown rendering that preserves code literally, including blank lines.
- Keyboard-accessible navigation and native modal focus behavior; unchanged
  polling results preserve focused controls and existing message nodes.
- Independent SQLite connections for sessions sharing the long-memory store.
- Session-capacity enforcement and shutdown cleanup.
- A reachable interactive CLI, clearer HTTP failures, and configured model
  overrides. `melo --serve` explicitly starts the gateway.
- Final assistant answers enter working memory, so later prompts can refer to
  earlier responses.
- Wheel package data includes both frontend assets and required scenario JSON.
- The existing Melo Akita artwork supplies welcome imagery, navigation and
  reply avatars, the favicon, and the Apple touch icon.
- Denied browser-storage access no longer blocks initialization or strands Send.
- Preparing a replacement chat at capacity cannot discard an existing chat when
  seeding fails or the existing chat becomes busy.

## Limits and next steps

- Browser recovery lasts only while the gateway process and session remain alive.
  Durable conversations across restarts are not implemented.
- Direct CLI sessions are independent from web sessions. A gateway-client CLI
  mode is required for shared Mac/iPhone/terminal conversations.
- Responses arrive when the run finishes; token/tool-event streaming is not yet
  implemented. Visible clients poll every 2.5 seconds.
- Stop cancels the harness task and provider request. Already dispatched model
  computation may finish independently inside a backend.
- Real embedding retrieval, external MCP services, vision, and other backend
  families were not part of the live oMLX smoke; their existing unit tests ran.
- No physical iPhone, iOS keyboard, background/lock-screen, or network-change
  testing was performed. The responsive check is not native-device validation.
- FastAPI/Starlette deprecation warnings remain; they do not fail the suite.
- The gateway has no remote authentication and remains bound to localhost for
  this review. See [Apple client direction](mobile-client-direction.md) for the
  proposed authenticated, persistent, multi-device control layer.
