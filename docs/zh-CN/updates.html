运行选项、运行结果和退出码

2026-10-22 · #25、#26、#27、#28、#30、#31、#32（审核中）

现在，直接模式下的一次 melo "<task>" 运行可以交给脚本或基准测试来驱动。

  • 运行选项：--max-steps、--attempt-policy、--tool-exposure、--builtins、--memory、--memory-dir 和 --timeout；在 --base-url 运行中启用长期记忆的 --embedding-base-url 和 --embedding-model；以及 Python API 中的 AgentOptions（#30）。
  • 每次运行都以九种状态之一结束。--output-format json 会把运行记录输出为一行 JSON；退出码在 completed 时为 0，crashed 时为 1，其他状态或用法错误时为 2（#30）。
  • 失败的模型请求在重试可能成功时会自动重试；--request-timeout 和 request_timeout_s 用来设置对话请求超时（#30）。
  • SIGTERM 和 SIGHUP 会在 8 秒内结束一次直接模式的运行，并保存它的任务记录（#30）。
  • 每一步只能运行本步提供的工具；内置工具的调用如果参数类型不对，会在运行前被拒绝（#30）。
  • 支持本地 MCP 服务器提供的工具（--mcp-config 和 --mcp-only），工具也可以返回图片（#27、#30）。
  • 工具调用会以真正的工具调用轮次发给兼容 OpenAI 接口的模型，一步中的每个调用都会执行；extra_body 可以为对话请求添加字段（#26）。
  • 反思的回复中没有 JSON 对象时，会不带工具再请求一次（#31）。
  • #32（审核中）：在检索模式下，每一步先提供所有已注册的内置工具，再提供对话中提到的工具和用带 IDF 的 BM25 检索到的工具，两部分都按名称排序。
  • 采用 MIT 许可证（#28），开发环境改用 uv，并把 uv.lock 提交到仓库（#25）。

真实后端的记忆测试结果已归档

2026-05-10 · #4

我们在三个本地服务器上测试了跨会话保存的长期记忆：oMLX、Ollama 和 MLC LLM，三者都使用同一个 Qwen3 0.6B 嵌入模型系列。三个服务器都完成了全部四个场景。得分和端到端耗时见归档的测试总结（英文）；这些数据是在 2026-05-10 的代码上测得的。oMLX 是一个兼容 OpenAI 接口的服务器，测试时通过它的接口连接，它不是内置后端。

持久化记忆、有上限的反思和配置检查

2026-04-29 · #8 至 #20

  • 持久化记忆（开启持久化后保存在 SQLite 中的历史记录和长期记忆）改用异步的 aiosqlite，写入会串行执行。
  • 工作记忆只保留最新的一条反思；反思超出长度上限时会停止运行，而不是让提示词越来越长。
  • 配置向导在保存配置之前，会先向每个服务器发送测试请求。
  • 智能体的模型封装 Chat 改为内部模块：Agent 是公开的入口。
  • 文档补充了每种模式的最小检查命令，tests/smoke/ 新增了针对真实本地后端的 pytest 检查。

后端注册表和按尝试运行的智能体循环

2026-03-29 · #5

  • 后端注册表：本地适配器支持 Ollama、MLC LLM、vLLM 和 SGLang，云端适配器支持 OpenAI、Anthropic、Google Gemini 和 NVIDIA。
  • 对话后端和嵌入后端分开选择（chat_backend 和 embedding_backend）。
  • 智能体循环按多次尝试运行，尝试之间进行结构化反思，再由一个判定决定是否继续。
  • 为 Ollama 自己的 API 提供对话提供方，能把模型的思考过程和回答分开。
  • 用于比较不同后端的基准测试场景和报告。

最初的代码结构

2026-03-25

  • 智能体移入 melo/，配置、提供方、网关和配置向导移入 support/。
  • 在 melo/ 中定义提供方接口，让智能体不依赖任何特定后端。
  • 为离线的 melo/sleep/ 包搭建了框架，智能体并不使用它。
  • 为新结构补充了测试。

早期预览版（pre-alpha）：在 v0.1.0 之前，命令和 API 都可能变化。
