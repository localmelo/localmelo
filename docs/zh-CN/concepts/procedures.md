# 程序性记忆

程序性记忆学习你反复运行的任务的步骤，例如每天修复的测试套件或每日报告，让进度显示可以展示一次运行进行到哪里。它保存以前的运行做了什么，而不是模型说了什么：工具调用的类别、短标签、步骤数量和时间。

每次运行都会写入：不论运行通过 `melo`、`melo ""` 循环、网关还是 Python API 执行，结束时都会添加记录。开启持久化时（见[记忆](../../guides/memory.md#keep-memory-between-runs)（英文）），记录写入记忆目录的 `procedures.db`；否则程序性记忆在智能体存续期间保留在 RAM 中，不写入文件。不想写入磁盘时，保持持久化关闭。这里的机制不会调用模型、进入提示或更改请求。

运行可能展示的信息通过 [`run.progress`](../../reference/events.md#runprogress)（英文）事件发送给使用 `progress=True` 请求它的 Python 调用方，也通过 `melo "<task>"` 在终端绘制的[进度行](../../reference/cli.md#progress-line)（英文）显示：首次运行显示事实，之后显示过去运行的步骤和时间。直接运行是独立进程，因此 `melo` 只有在持久化开启时才显示过去的运行。级别 2，即进度条，在本版本中关闭：在已记录运行上的回放表明，门控在两个测试集上都还未以所需余量（0.05）挡住不准确的进度条，因此运行最多显示级别 1；等一组重复运行通过回放后，后续版本才会开启级别 2。`melo-procedures` 在已记录运行上回放规则，以便在运行显示任何内容之前衡量这些规则。

<a id="what-a-run-does"></a>

## 一次运行做什么

- **开始时**，只有请求了进度时（Python 调用方请求，或 `melo` 绘制进度行），运行才查找一次所属例程，最多等待 1 秒；没有模板或查找失败时，只显示事实（级别 0）。
- **运行期间**，它在 RAM 中保存轨迹：每一步及每次工具调用的类别和标签。不保存工具输出；测试调用输出的最后 400 个字符用于读取摘要，随后丢弃。
- **结束时**，在最后一个事件之后，它添加例程（如果是新例程）、本次记录，以及完成时的下一版模板。这需要几毫秒，最多 2 秒；写入失败则跳过，并在日志写一行 INFO。被取消，或在 SIGTERM 或 SIGHUP 后结束的运行不添加任何内容。
- 本次记录会记录门控给出的级别，包括门控给出级别 2 但实际显示级别 1 的情况；门控通过时还会记录进度条本应产生的误差，为开启级别 2 提供证据。门控使用运行开始时请求进度所查到的结果；否则，由于这样的运行在开始时不读取任何内容，就使用结束时例程模板给出的结果。
- Python 中的 `run_task(..., routine="name")` 或 `melo --routine name` 让不同文件夹、不同措辞的运行归入同一个指定名称的例程。

<a id="how-it-works"></a>

## 工作方式

- **例程。** 重复进行的任务。作为查询提供的任务由标准化查询和它的*位置*识别：位置是工具工作的目录，即工作区根目录；没有工作区时为当前工作目录。标准化执行 NFKC、转为小写、合并空白，并将日期和时间遮蔽为 `<date>` 和 `<time>`（ISO 日期、`10/26`、`10/26/2026`、`26.10.2026`、带日期或年份的月份名、星期名、`2026年`、`10月26日`、`星期一`、`周一` 和 `HH:MM[:SS]`）。其他数字保留："fix issue 123" 和 "fix issue 456" 是两个例程。指定名称的例程在任何文件夹中都是同一个例程。
- **相似任务。** 当文件夹至少已有 5 个其他例程时，新例程会用标准化查询的 BM25 与该文件夹最新的 1,000 个例程比较。明显的最佳匹配向本次运行提供其命名步骤和过去事实，按级别 1 显示：只是提示，绝不是进度条。本次运行仍建立自己的例程。
- **单次记录（episode）。** 一个例程的一次已结束运行：状态、步骤、尝试次数、时长以及*片段*，即类别和目标相同的连续工具调用序列。
- **模板。** 同一例程、同一模型和同一组影响长度的选项（`attempt_policy`、`reflection_gate`、`max_steps`、`steps_per_attempt`、`max_attempts`）下，多次运行的共同信息：步骤统计和命名步骤。每次完成的运行都会添加一个新版本，根据最近 8 次完成的运行计算。
- **级别。** 显示可以从模板中展示的内容：

  | 级别 | 条件 | 显示 |
  |---|---|---|
  | 0 | 没有模板：首次运行、不同模型或其他选项 | 仅事实：步骤、尝试、阶段、测试 |
  | 1 | 有一次完成的运行；或门控失败；或相似任务；或模型被降级或没有 ID | 过去运行的步骤、时间和命名步骤，不显示百分比 |
  | 2 | 门控通过 | 还显示进度条（本版本关闭：运行显示级别 1） |

- **门控。** 级别 2 要求例程自己的键或名称、模型 ID、窗口中至少 2 次完成的运行，以及不超过 0.5 的*离散度*（最长步骤数减最短步骤数，再除以中位数）。某个模型最近 10 次已评分运行（至少 5 次）的进度条平均误差超过 0.18 时，会被降到级别 1，直到表现改善。模板的首次运行是探索：再有 2 次运行完成后，如果首次运行已完成且步骤多于后面所有运行，就将其移出统计。
- **进度条。** 第 k 步开始后，以窗口中位数为 m：当 k < m 时为 k ÷ m；否则为 k ÷（k + 较长运行的剩余步骤中位数），没有更长运行时为 k ÷（k + 1）。进度条永不后退，运行中不超过 95%，只有运行完成时才到 100%。运行超过窗口中所有运行、窗口未预期的反思或卡住通知会让进度条在本次运行剩余时间内冻结。只有进度条可以离开模板；级别 1 下运行保持 `running`。

<a id="classes-and-phases"></a>

### 类别与阶段

每个工具调用归入一个类别：

| 类别 | 调用 |
|---|---|
| `R` | `file_read`；以读取程序（`ls`、`cat`、`grep` 等）开头的 `shell_exec`；读取或打印的 `python_exec` 代码 |
| `W` | `file_write`；执行写入的 `shell_exec`（`>`、`mv`、`cp`、`mkdir`、`rm`、`sed -i`、`tee`、`touch` 等）；写入文件的 `python_exec` 代码 |
| `T` | 除 `file_read` 和 `file_write` 外，命令、代码或参数提到 `pytest`、`unittest`、`_test.py`、`verify`、`check` 或 `assert ` 的调用；对 `shell_exec` 和 `python_exec`，此规则先于 `R` 和 `W` 检查 |
| `X` | 其他所有调用 |

当 `T` 调用输出的最后 400 个字符包含至少一次通过且没有失败或错误的 pytest 或 unittest 摘要时，它才算*通过*。仅凭退出状态绝不算通过：智能体可能将测试通过管道传给 `tail` 或 `grep`。失败的调用，以及输出以 `[exit code <n>]` 开头的调用，都不算通过。

阶段从类别推断：第一次写入前为 **Explore**，然后是 **Write**、**Verify**，第一次通过后是 **Finishing**。*循环*指写入之后的测试。

调用标签不包含参数内容：`Read parser.py`、`Edit parser.py`、程序及其第一个子命令（`pytest`、`git status`、`npm test`）、`Python`，或 MCP 工具名。标签和例程保存的查询一样经过最小脱敏（见[隐私](../../guides/memory.md#privacy)（英文）），并截断至 40 个字符。shell 标签只从命令的前 2,000 个字符读取，绝不从引号内部读取。作为 argv 数组（字符串列表）发送的 `shell_exec` 命令会被工具拒绝，但在分类和标记时先用 `shlex.join` 合并为一个命令文本，因此类别和标签也来自其中的词。

<a id="the-store"></a>

## 存储

`SqliteProcedures` 将程序性记忆保存在记忆目录中的 `procedures.db`，权限为 0600；`MemoryProcedures` 将其保存在 RAM 中。两者都位于 `localmelo.melo.memory.procedures.store`。文件采用架构版本 1（`PRAGMA user_version`），有三张表：

| 表 | 每行代表 | 变化 |
|---|---|---|
| `routines` | 例程：键、名称、标准化并脱敏的查询（最多 2,000 个字符）、位置，以及相似的例程 | 从不变化 |
| `episodes` | 已结束运行：例程、模板、模型、构建版本、匹配、级别、状态、步骤、尝试次数、工具调用、时长、第一次通过、循环、片段和影子进度条误差 | 从不变化 |
| `templates` | 模板的一个版本：统计、命名步骤、参数、来源运行、父版本、状态、来源 | 仅 `status`：`active` → `superseded`，`candidate` → `active` 或 `rejected`；被拒绝候选的 `eval_json` 可记录原因 |

文件中的触发器拒绝任何其他更改，一个模板最多只有一个 `active` 版本。运行结束时在一个 `BEGIN IMMEDIATE` 事务中写入，因此两个进程同时完成同一例程的运行时会互相等待（最多 500 毫秒）。只有 `melo-procedures forget` 会从文件中删除行。

后续的睡眠任务可以提出一个版本：它添加一个 `candidate` 及其在留出运行上的回放结果（`heldout_task_ids`、`bar_error`、`parent_bar_error`、`cap_share`、`longer_rate`、`reason`）。只有当误差低于父版本、最多 5% 的步骤停在 95%，且父版本仍是活动版本时，它才会成为活动版本；否则为 `rejected`，若另一版本先成为活动版本，原因是 `stale`。之后的在线版本保留睡眠任务的命名步骤，只刷新统计。
