快速开始

安装 localmelo，在你自己的模型服务器上运行第一个任务，保存配置并启动网关。

开始之前

  • macOS（在 macOS 上开发和测试）或 Linux（应该也能运行，但尚未测试）；不支持 Windows。
  • Python 3.11 或更高版本、Git 和 uv（也可以用 pip，见用 pip 安装）。
  • 一个模型服务器。下面的命令使用 Ollama，模型用 ollama pull qwen3:8b 下载。
  • 在搭载 Apple 芯片的 Mac 上推荐 oMLX：改用 http://127.0.0.1:8000/v1 和模型文件夹的名称。
  • 任何 OpenAI 兼容的服务器也可以：使用它的 /v1 地址和模型名称。

五步上手

  1. 安装

    克隆仓库，让 uv 完成安装。

  2. 运行第一个任务

    让 melo 连接你的模型服务器并提一个问题，答案会打印在 stdout。

  3. 打开主对话

    不带任务运行 melo：首次运行会找到你的服务器并保存配置。

  4. 交给它一个任务

    在对话里提出更大的工作：它会成为任务，完成后以卡片回来。

  5. 查看它记住了什么

    melo 跨对话保存笔记；你可以列出它们，或忘掉某一条。

安装

  • uv 创建 .venv/（需要时会安装 Python 3.13），并装好网关的依赖。
  • 请保留目录名 localmelo：改名的目录或 ZIP 下载会报错 ModuleNotFoundError: No module named 'localmelo'。
  • 激活只对当前终端有效；在其他地方用 uv run --project <clone> melo …。
  • 在搭载 Apple 芯片的 Mac 上，uv run python scripts/build_macos_app.py --install 会把 App 构建到 ~/Applications。

用 pip 安装

python3 必须是 Python 3.11 或更高版本；-e 让安装始终链接到这份代码。

运行第一个任务

模型可以运行 shell 命令和 Python 代码，也可以读写你能访问的任何文件：没有沙箱。要在不使用工具的情况下运行任务，请加上 --builtins none。见安全策略（英文）。

使用 oMLX 时，用它的地址和模型文件夹的名称：

  • 答案打印在 stdout 上，退出码为 0（echo $? 打印 0）。
  • -u（--url）为本次运行指定服务器，不读配置文件；-m（--model）指定模型。
  • 它不发送 API 密钥：使用云端 API 时，请保存配置（见下文）。
  • 全部选项见命令行参考。

以 JSON 格式获取结果

  • stdout 中正好是一行 JSON；只有 status 为 completed 时退出码才是 0。

运行结果

  • status 说明运行如何结束，例如 completed、budget_exhausted 或 provider_error。
  • 计数字段给出步数、模型请求数和工具调用数；config 记录运行用的选项。
  • 运行结果列出了每个状态和字段。

保存配置

在终端里运行 melo。还没有保存配置时，它会找到这台电脑上的模型服务器，询问是否使用，并保存 ~/.cache/localmelo/config.toml：

  • 此后，melo 和 melo "<task>" 都使用保存的服务器。
  • 每个问题都是一个列表：↑ ↓ 移动，Enter 确认，Esc 选择安全的答案。
  • 没有服务器在运行时，受支持的 Apple silicon Mac 会显示只读设置预览：oMLX、Qwen3 4B Instruct（约 2.28 GB）、已缓存文件、磁盘空间和生命周期。Set up and start 目前只显示手动步骤，不是安装程序；不会下载、启动或保存任何东西。其他平台保留手动说明，仍可选择 Check again。
  • 细节见首次运行和设置嵌入模型。

使用配置向导

配置向导还能设置嵌入服务器或云端 API。使用云端 API 时，先运行 export OPENAI_API_KEY="<your key>"（或你所用服务商的变量）。

提示输入什么
Use this model server?它找到的服务器，或选 Use another server 打开完整菜单。
Chat backend你的服务器类型，例如 2. Ollama (local endpoint)，或者一个云服务商。
Base URL服务器地址；按 Enter 采用方括号中的默认值。Ollama 的地址不带 /v1。
Chat model name模型，例如 qwen3:8b。
Embedding backend5. None (no long-term memory)，或对话服务器列出的一个嵌入模型。
  • 保存之前，向导会向每个服务器发送一个简短的测试请求。
  • 检查失败时，选择 Try again、Save anyway 或 Cancel setup。
  • 成功时打印 Config saved to …；然后 melo serve 在 http://127.0.0.1:8401 上启动网关。

  • 健康检查不会联系模型服务器；运行任务才会。
  • 在这台电脑的终端里，melo serve 会在浏览器中打开控制台；melo console 可再次打开。
  • 通过 SSH 时，melo console 打印一个一次性链接，需在 60 秒内打开；不要分享它。

  • melo-task 创建并控制网关的任务。

交互式对话

  • 每个工具调用显示为一行，答案以 Markdown 打印；开发者模式还会显示步骤、阶段和本次运行的进度事实。
  • 输入 / 查看命令：/help、/model、/status、/attach PATH、/new；Ctrl+D 退出。
  • 运行 shell 命令、Python 代码或写文件之前，melo 会先问你：允许一次、在本会话中允许，或拒绝并说明原因。
  • melo 在当前文件夹中工作（-w DIR 指定其他文件夹）；Esc 停止一轮。
  • 按键和其余内容见交互式界面。
  • http://127.0.0.1:8401/ 上的控制台使用网关的模型；在 Settings 或用 melo setup 修改。
  • 首次运行时，欢迎页会找到这台 Mac 上的模型服务器，点 Use this model 即可连接。
  • 对话保存在网关的 sessions.db 中，重启后仍在。
  • 审批卡片显示写文件将做出的改动；它们不是防御同一用户进程的安全边界。
