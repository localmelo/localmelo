快速开始

本教程会安装 localmelo，在本地模型服务器上运行第一个任务，然后保存配置并启动网关。

开始之前

你需要：

  • macOS（在 macOS 上开发和测试）或 Linux（应该也能运行，但尚未测试）。不支持 Windows。
  • Python 3.11 或更高版本、Git，以及 uv（也可以用 pip，见用 pip 安装）。
  • 一个模型服务器。下面的命令使用 Ollama：安装并启动它，然后用 ollama pull qwen3:8b 下载一个模型。在 Apple 芯片的 Mac 上，推荐使用 oMLX：在命令中改用 http://127.0.0.1:8000/v1 和你的模型文件夹名。任何兼容 OpenAI API 的服务器也都可以：填写它的 /v1 地址和模型名即可。

安装

git clone https://github.com/localmelo/localmelo.git
cd localmelo
uv sync --extra gateway
source .venv/bin/activate

uv 会创建虚拟环境 .venv/（如果你没有 Python 3.13，它会自动安装），并安装 localmelo 及网关所需的依赖。

请保留目录名 localmelo：软件包就是从这个目录构建的。重命名后的目录或 ZIP 下载（localmelo-main）会报错 ModuleNotFoundError: No module named 'localmelo'。

在 Apple 芯片的 Mac 上，macOS 开发应用会在控制台外面套上一个原生窗口。一条命令 uv run python scripts/build_macos_app.py --install 就能构建它、做临时签名（ad hoc），并安装到 ~/Applications，不需要管理员权限。它不需要 Apple 开发者账号，只留在构建它的这台 Mac 上，而且需要正式版 Xcode：它是开发包，不是经过公证的发行版，也不是 Homebrew cask。

本教程后面的命令直接调用 melo。激活虚拟环境只对当前终端有效：打开新终端后，需要再次运行 source <clone>/.venv/bin/activate，其中 <clone> 是你的 localmelo 目录。使用 uv 时，也可以在克隆目录中运行 uv run melo …，或在其他任何位置运行 uv run --project <clone> melo …。

用 pip 安装

git clone https://github.com/localmelo/localmelo.git
cd localmelo
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[gateway]"

python3 必须是 Python 3.11 或更高版本。-e 会让安装保持与当前源码目录的关联，修改源码后不必重新安装。

运行第一个任务

模型可以运行 shell 命令和 Python 代码，也可以读写你能访问的任何文件：没有沙箱。如果想让任务不使用任何工具，请加上 --builtins none。详见安全策略（英文）和检查能做什么（英文）。

melo -u http://127.0.0.1:11434/v1 -m qwen3:8b "What is 6*7?"

答案会输出到 stdout，命令的退出码为 0（echo $? 会输出 0）。-u（--url）让 localmelo 在这一次运行中直接连接一个兼容 OpenAI 接口的服务器，不需要配置文件，-m（--model）指定模型。旧写法 --base-url 和 --chat-model 仍然可用（旧写法对应的新写法）。它不会发送 API 密钥，所以适合本地服务器；使用云端 API 时，请先保存配置（见下文）。

使用 oMLX 时，填写它的地址和模型文件夹的名称：

melo -u http://127.0.0.1:8000/v1 -m Qwen3-8B-4bit "What is 6*7?"

所有选项见命令行参考（英文）。

以 JSON 格式获取结果

melo -u http://127.0.0.1:11434/v1 -m qwen3:8b -o json "What is 6*7?"

示例输出（具体数值会不同）：

{"task_id": "f52e785a84a144ff8c3b8e70e0451eb1", "status": "completed", "result": "42", "error": "", "steps": 1, "attempts": 1, "n_llm": 1, "n_main": 1, "n_aux": 0, "n_tool": 0, "llm_errors": 0, "usage": {"prompt_tokens": 120, "completion_tokens": 12, "total_tokens": 132}, "duration_s": 1.9, "config": {"max_steps": 30, "attempt_policy": "reflect", "steps_per_attempt": 10, "max_attempts": 5, "reflection_gate": "flags", "tool_exposure": "retrieve", "mode": "direct", "builtins": ["file_read", "file_write", "python_exec"], "memory": true, "memory_dir": null, "timeout_s": null, "tools": ["file_read", "file_write", "python_exec"]}, "localmelo_version": "603f40d"}

stdout 上只有这一行。只有当 status 为 completed 时，退出码才是 0。

运行结果

status 表示运行是如何结束的，例如 completed、budget_exhausted 或 provider_error。各个计数字段记录这次运行用了多少步、多少次模型请求和多少次工具调用，config 记录运行时使用的选项。所有状态和字段的说明见运行结果。

保存配置

配置文件会保存后端设置，这样 melo、melo "<task>" 和网关都不再需要 -u。

使用本地服务器时，在终端里运行 melo。还没有配置时，它先说明自己需要什么：本机上的一个模型服务器。随后在本机查找（oMLX 在 8000 端口，Ollama 在 11434 端口），询问服务器地址（按回车接受找到的地址），再从服务器列出的模型里选一个（列表先列对话模型，嵌入或重排模型会加标签），保存 ~/.cache/localmelo/config.toml，然后打开交互式界面：

$ melo
melo uses a model server on this computer (oMLX, Ollama, LM Studio…).
Found a model server at http://127.0.0.1:11434/v1 (1 model).
Server URL [http://127.0.0.1:11434/v1]:
✓ http://127.0.0.1:11434/v1 lists 1 model; using qwen3:8b.
No embedding model on this server. ollama pull qwen3-embedding:0.6b, then melo setup.
Saved to ~/.cache/localmelo/config.toml (melo setup changes it).
melo 0.1.0 · qwen3:8b (/model to change)
~/demo-project
Try: What is this project? · / commands · ctrl+d quit

第一行显示软件包版本；在 git 检出中还会显示短提交号，如 melo 0.1.0 (baab21e)。melo --version 输出同一行并以退出码 0 退出。/status 显示服务器、工具、记忆和会话。

输入一条消息后按回车，或用 /exit 退出。以后运行 melo 会直接进入，melo "<task>" 也会使用保存的服务器。这里用的是 Ollama，所以它被保存为 ollama 后端；oMLX 服务器保存为 omlx，其他兼容 OpenAI 接口的服务器保存为 vllm。如果服务器还列出了嵌入模型，首次运行会多问一句 Use <model> for long-term memory? [Y/n]:。详见首次运行（英文）和设置嵌入模型（英文）。

使用配置向导

配置向导还可以设置嵌入服务器或云端 API，并在完成后启动网关。使用云端 API 时，请先在这个终端中运行 export OPENAI_API_KEY="<your key>"（或你所用服务商对应的变量）：向导的测试请求会用到这个密钥。

melo --serve --reconfigure

向导会依次询问：

提示填写内容
Chat backend你的服务器类型对应的编号，例如 Ollama 是 2。默认值是已保存的后端，没有时是 [1]（MLC）。oMLX 或其他兼容 OpenAI 接口的服务器请选择 oMLX 或 vLLM（3）。
Base URL服务器地址。按回车接受方括号中显示的默认值：已保存的地址，没有时是该后端的常用地址。
Chat model name模型名，例如 qwen3:8b。
Save and continue?按回车（表示“是”）保存并继续。
Embedding backend5 表示 None (no long-term memory)。没有保存过嵌入后端时，对话服务器自己列出的嵌入模型会作为 6、7…… 追加，第一个是默认值；选中一个即可。
Embedding endpoint URL、Embedding model name只有选择了固定的嵌入后端 1–4 时才会询问；选择检测到的模型时不会询问。

使用云端 API 时，请选择对应的服务商。向导接着会询问 API key env var（即你导出的那个变量的名字）和 Chat model，而不是 Base URL 和 Chat model name。

Ollama 的默认地址 http://localhost:11434 没有 /v1，这是正确的：ollama 后端使用 Ollama 自己的 API，而不是兼容 OpenAI 的 API。

接着，向导会向每个服务器发送一个简短的测试请求（Probing backends ...）。如果对话服务器没有响应，它会输出 Probe failed: … 并询问 [r]etry, [s]ave anyway, [N]o [N]:；输入 r 会重新询问地址和模型，直接按回车则什么也不保存。如果只有嵌入服务器失败，向导会关闭嵌入后保存，并给出提示。成功时，它会输出 Config saved to …（后面是 ~/.cache/localmelo/config.toml 的路径），然后启动网关，地址为 http://127.0.0.1:8401。网关会一直在这个终端中运行。单独运行 melo setup 时，改为打开交互式界面；在默认模式下它先问首次运行的那个问题：显示 Found a model server at … 并询问 Use it? [Y/n]:。只有回答 n、没有找到服务器或使用 --developer 时，才会出现上面的完整菜单。

设置嵌入模型

长期记忆需要一个嵌入模型。localmelo 从不下载或启动模型：请让它使用你的服务器已经提供的模型。指南（英文）覆盖 Ollama、oMLX、vLLM、SGLang 和 MLC。

使用 Ollama 时：

ollama pull qwen3-embedding:0.6b
curl -sS http://127.0.0.1:11434/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model": "qwen3-embedding:0.6b", "input": "ping"}'
melo setup    # Embedding backend: 2 (Ollama); URL http://localhost:11434; model qwen3-embedding:0.6b

回复中必须包含非空的 data[0].embedding。nomic-embed-text 是更小的纯英文替代品。

使用 oMLX 时，对话服务器也提供嵌入模型：

curl -sS http://127.0.0.1:8000/v1/models
curl -sS http://127.0.0.1:8000/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model": "Qwen3-Embedding-0.6B", "input": "ping"}'

GET /v1/models 只给出 id，不给出类型，所以要用上面的嵌入请求来确认。保留原来的对话服务器，并设置 embedding_backend = "vllm" 以及该表的 embedding_url 和 embedding_model；见oMLX（英文）。

更换模型会改变向量空间：维度不同的旧向量会被跳过，旧条目不再参与排序。要回收空间，请先停止 localmelo，再删除 ~/.cache/localmelo/memory/long_term.db*。

启动网关

如果你是用 melo 保存的配置，请用 melo serve 启动网关；上面的向导会自己启动网关。在第二个终端中检查网关，并通过它运行一个任务：

在终端运行 melo console，在 60 秒内打开私密的一次性链接。API 示例通过管道把网关令牌传给 curl，不会将令牌放进命令行参数或 shell 历史记录。请勿启用 curl 的详细输出或记录请求头；同一用户的进程仍可读取令牌文件。

{ printf 'Authorization: Bearer '; cat ~/.cache/localmelo/gateway/auth/token; printf '\n'; } | curl -H @- http://127.0.0.1:8401/v1/health
{ printf 'Authorization: Bearer '; cat ~/.cache/localmelo/gateway/auth/token; printf '\n'; } | curl -H @- -X POST http://127.0.0.1:8401/v1/agent/run \
  -H "Content-Type: application/json" \
  -d '{"query": "What is 6*7?"}'

示例输出（具体数值会不同）：

{"status":"ok","uptime":12.3,"sessions":{"active":0,"busy":0,"max":50},"chat_backend":"ollama","embedding_backend":"none"}
{"result":"42","session_id":"a7e8f646ca2e"}

健康检查不会连接模型服务器，运行任务时才会。在浏览器中打开 http://127.0.0.1:8401/ 即可使用网页工作区（见交互式对话）。

在第一个终端中按 Ctrl+C 停止网关。运行任务会使用保存的配置：

melo "What is 6*7?"

以后想跳过向导、直接启动网关时，运行 melo serve。

独立的 melo-task 客户端通过认证的回环 HTTP 创建、查看、跟随和控制网关任务，从不启动网关。详见任务命令。

交互式对话

不带任务运行 melo，即可在终端里对话。轮次运行时会实时显示它的工作：模型的思考、每个工具调用完成时的命令或文件、重试、通知和反思，实时区域显示步数、阶段、正在运行的工具和本次运行的进度事实。答案按 Markdown 输出：

melo
# Or talk to an OpenAI-compatible server that is not saved. Without
# -m it uses the server's only chat model or its one loaded model;
# with several chat models and not exactly one loaded, it exits 2 and lists them:
melo -u http://127.0.0.1:8000/v1
melo -u http://127.0.0.1:8000/v1 -m YOUR_MODEL_ID
  • 输入 / 查看命令：/model 列出服务器上的模型并切换到其中一个，/backend 切换到另一个服务器（两者都会保存为默认值），/verbose 和 /thinking 增减细节，/expand 打印某个工具调用的完整输出，/progress 显示实时区域依据的进度事实，/approvals 显示审批模式和授权，/status 显示会话的各项事实，/mcp 显示 MCP 服务器，/retry 重新运行最近的一轮，/attach PATH 把一个工作区文本文件（最大 256 KiB）暂存到下一条消息，/attachments 和 /detach N|all 列出和移除已暂存的文件，/new 重新开始，/exit 或 Ctrl+D 退出。
  • melo 在运行 shell 命令、Python 代码或写文件之前会先询问：按 1 允许这一次，按 2 在本次会话中允许这个工具，按 3 拒绝并告诉 melo 原因。按 Esc 停止当前轮次。
  • melo 在当前文件夹中工作（-w DIR 可以换一个）：文件工具只能在其中操作；命令和 Python 可以访问其他文件，所以 melo 会先询问。

按键和其余细节见交互式界面（英文）。melo "" 打开的是早先版本的简单对话循环。没有终端时，单独的 melo 会以退出码 2 结束；请用 melo serve 启动网关。

http://127.0.0.1:8401/ 上的网页工作区就是控制台的实时页面，只访问 /api：它使用网关配置的模型，可以在连接设置中或用 melo setup 修改。它按最新在前列出你的对话，支持搜索和每个对话各自的草稿，并像终端一样显示一轮：你的消息、每个工具调用一张工作卡片、折叠的推理和反思、通知、实时进度行，以及带事实和 Copy response 的答案。Stop 会取消轮次，等待中的审批显示为 Needs approval，对话保存在网关的 sessions.db 中，所以重启后仍然保留。同一网关上的其他浏览器标签页会看到相同的对话。审批卡片让你允许或拒绝工具调用，设置对话框用于配置连接；Workers 区域以只读方式显示保存的 worker 运行记录。网关要求认证，可用 melo console 登录；审批不能防止同一用户的进程或其他本机服务访问。

用 oMLX 提供模型

oMLX 在搭载 Apple 芯片、macOS 15 或更高版本的 Mac 上，通过兼容 OpenAI 的 API 提供 MLX 模型。localmelo 支持把它作为本地服务器：首次运行时的设置会在 8000 端口找到它，并询问它哪些模型已加载。在配置文件中它是 vllm 后端，也可写作 omlx；原因见指南（英文）。用它代替 Ollama 的步骤：

  1. 用 Homebrew 安装 oMLX：

    brew tap jundot/omlx https://github.com/jundot/omlx
brew install jundot/omlx/omlx

    oMLX 的 macOS 应用也会安装这个命令，路径是 ~/.omlx/bin/omlx。其他安装方式见它的 README。上面的 Homebrew 命令安装的 oMLX 不带可选的原生内核；少数模型系列（例如 Qwen3.5）需要这些内核才能全速运行。应用已内置这些内核，README 说明了 Homebrew 的相关选项。

  2. 把每个模型放进同一个模型目录下的独立子文件夹。oMLX 会提供每个含有模型（config.json 和权重）的子文件夹，子文件夹的名字就是模型 ID。例如用 Hugging Face 命令行（hf，可用 uv tool install huggingface_hub 安装）下载：

    hf download mlx-community/Qwen3-8B-4bit --local-dir ~/models/Qwen3-8B-4bit

  3. 启动服务器，并让它在单独的终端里一直运行：

    omlx serve --model-dir ~/models --port 8000

    它监听 http://127.0.0.1:8000。oMLX 会把 --model-dir 和 --port 保存到自己的 settings.json（默认在 ~/.omlx 下），之后不写这些参数时就用保存的值，所以以前保存过的端口会覆盖默认的 8000；写上 --port 就不会有这个问题。oMLX 应用和 omlx start 会改在后台运行服务器，使用 oMLX 中保存的文件夹和端口（Homebrew 服务默认使用 ~/.omlx/models 和 8000 端口）：此时可以跳过上面的命令。

    保持默认的主机地址，不要设置 --api-key：localmelo 不会向本地服务器发送 API 密钥。如果请求返回 HTTP 401（API key required），说明之前在 oMLX 的管理页面或用 OMLX_API_KEY 设置过密钥：在管理页面的设置里打开 Allow inference without API key，或取消 OMLX_API_KEY。开启该设置后，列出模型和对话都可以使用，但 oMLX 仍要求用密钥访问报告哪些模型已加载的路由，因此设置无法标出已加载的模型（见下文）。

  4. 确认服务器列出了这个模型：

    curl -sS http://127.0.0.1:8000/v1/models

    返回的 data 列表里有一项 "id": "Qwen3-8B-4bit"。它也可能列出你 Hugging Face 缓存里的 MLX 模型。如果显示 Failed to connect，说明这个端口上没有服务在监听：看一下 oMLX 启动日志里的端口。如果显示 API key required，说明设置过密钥：见第 3 步。

  5. 用这个 ID 运行一个任务：

    melo -u http://127.0.0.1:8000/v1 -m Qwen3-8B-4bit "What is 6*7?"

    oMLX 在第一次请求时才加载模型，大模型可能要一分钟左右。如果这次请求超时，加上 -X request_timeout_s=600（-X KEY=VALUE 只为这一次运行修改一项设置）。不指定 -m 时，melo 会询问 oMLX 有哪些模型，并使用唯一的对话模型或已加载的那一个，对任务和不带任务的 melo -u http://127.0.0.1:8000/v1（交互式界面）都是如此；有多个对话模型、且不是恰好一个已加载时，以退出码 2 结束，列出这些模型，并要求使用 --chat-model <id>。用 -m 指定模型可以跳过这次查询。

要把 oMLX 设为默认：在还没有任何配置时，在终端里运行 melo，它会在 8000 端口找到 oMLX，列出模型并保存你选的那个；首次运行（英文）展示了整个过程。oMLX 在第一个请求到达时才加载模型，因此列出的模型不一定在内存中，加载大模型可能要几分钟。所以设置按下面的方式选择；列出多个对话模型时，它会向 oMLX 询问哪些模型已加载（GET /v1/models/status，最多等一秒）：

  • 只有一个对话模型：它就是默认值。
  • 有多个，且 oMLX 说明了哪些已加载：设置会给已加载的模型标上 (loaded)，并以其中第一个作为默认值。
  • 有多个，但没有已加载的，或者 oMLX 没有说明：没有默认值。请输入要使用的模型的编号；只按 Enter 会再次询问，因为替你选择可能会开始漫长的大模型加载。设置了密钥时，即使开启了 Allow inference without API key，oMLX 也不会说明，此时设置会输出 The server did not say which models are loaded (it needs a key for that). 在 oMLX 中设置了别名的模型会以别名列出，状态回复会在文件夹名旁边给出该别名（model_alias，oMLX 0.7.1rc1 就是这样发送的），所以该模型会被标出，并且可以在别名下成为默认值。状态回复中没有别名的服务器无法标出这样的模型。

已经有配置时，先完成第 5 步，让模型加载好，再运行 melo setup：在默认模式下，它会用首次运行的问题提供它找到的服务器。在完整菜单中（回答 n 之后，或使用 --developer），对话后端选 oMLX 或 vLLM（3），输入 http://127.0.0.1:8000/v1 和模型 ID；除非 oMLX 也提供嵌入模型，嵌入后端选 5（None）。保存的文件，以及关闭 Qwen3 模型思考要加的配置，见配置（英文）。网页工作区随后会使用这个模型；它读取配置文件。
