快速开始

本教程会安装 localmelo，在本地模型服务器上运行第一个任务，然后保存配置并启动网关。

开始之前

你需要：

  • macOS（在 macOS 上开发和测试）或 Linux（应该也能运行，但尚未测试）。不支持 Windows。
  • Python 3.11 或更高版本、Git，以及 uv（也可以用 pip，见用 pip 安装）。
  • 一个模型服务器。本教程使用 Ollama：安装并启动它，然后用 ollama pull qwen3:8b 下载一个模型。任何兼容 OpenAI API 的服务器也都可以：在下面的命令中换成它的 /v1 地址和模型名即可。

安装

git clone https://github.com/localmelo/localmelo.git
cd localmelo
uv sync --extra gateway
source .venv/bin/activate

uv 会创建虚拟环境 .venv/（如果你没有 Python 3.13，它会自动安装），并安装 localmelo 及网关所需的依赖。

请保留目录名 localmelo：软件包就是从这个目录构建的。重命名后的目录或 ZIP 下载（localmelo-main）会报错 ModuleNotFoundError: No module named 'localmelo'。

本教程后面的命令直接调用 melo。激活虚拟环境只对当前终端有效：打开新终端后，需要再次运行 source <clone>/.venv/bin/activate，其中 <clone> 是你的 localmelo 目录。使用 uv 时，也可以在克隆目录中运行 uv run melo …，或在其他任何位置运行 uv run --project <clone> melo …。

用 pip 安装

git clone https://github.com/localmelo/localmelo.git
cd localmelo
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[gateway]"

python3 必须是 Python 3.11 或更高版本。-e 会让安装保持与当前源码目录的关联，修改源码后不必重新安装。

运行第一个任务

模型可以运行 shell 命令和 Python 代码，也可以读写你能访问的任何文件：没有沙箱。如果想让任务不使用任何工具，请加上 --builtins none。详见安全策略（英文）和检查能做什么（英文）。

melo --base-url http://127.0.0.1:11434/v1 --chat-model qwen3:8b "What is 6*7?"

答案会输出到 stdout，命令的退出码为 0（echo $? 会输出 0）。--base-url 让 localmelo 在这一次运行中直接连接一个兼容 OpenAI 接口的服务器，不需要配置文件。它不会发送 API 密钥，所以适合本地服务器；使用云端 API 时，请先保存配置（见下文）。

所有选项见命令行参考（英文）。

以 JSON 格式获取结果

melo --base-url http://127.0.0.1:11434/v1 --chat-model qwen3:8b --output-format json "What is 6*7?"

示例输出（具体数值会不同）：

{"task_id": "f52e785a84a144ff8c3b8e70e0451eb1", "status": "completed", "result": "42", "error": "", "steps": 1, "attempts": 1, "n_llm": 1, "n_main": 1, "n_aux": 0, "n_tool": 0, "llm_errors": 0, "usage": {"prompt_tokens": 120, "completion_tokens": 12, "total_tokens": 132}, "duration_s": 1.9, "config": {"max_steps": 30, "attempt_policy": "reflect", "steps_per_attempt": 10, "max_attempts": 5, "reflection_gate": "flags", "tool_exposure": "retrieve", "builtins": ["file_read", "file_write", "python_exec", "shell_exec"], "memory": true, "memory_dir": null, "timeout_s": null, "tools": ["file_read", "file_write", "python_exec", "shell_exec"]}, "localmelo_version": "603f40d"}

stdout 上只有这一行。只有当 status 为 completed 时，退出码才是 0。

运行结果

status 表示运行是如何结束的，例如 completed、budget_exhausted 或 provider_error。各个计数字段记录这次运行用了多少步、多少次模型请求和多少次工具调用，config 记录运行时使用的选项。所有状态和字段的说明见运行结果（英文）。

保存配置

配置文件会保存后端设置，这样 melo "<task>" 和网关都不再需要 --base-url。配置文件由配置向导生成。使用云端 API 时，请先在这个终端中运行 export OPENAI_API_KEY="<your key>"（或你所用服务商对应的变量）：向导的测试请求会用到这个密钥。

melo --serve --reconfigure

向导会依次询问：

提示填写内容
Chat backend你的服务器类型对应的编号，例如 Ollama 是 2。默认值 [1] 是 MLC。其他兼容 OpenAI 接口的服务器请选择 vLLM（3）。
Base URL服务器地址。按回车接受方括号中显示的默认值。
Chat model name模型名，例如 qwen3:8b。
Start?按回车（表示“是”）继续。
Embedding backend如果没有嵌入服务器，输入 5，即 None (no long-term memory)。
Embedding endpoint URL、Embedding model name只有选择了嵌入后端时才会询问。

使用云端 API 时，请选择对应的服务商。向导接着会询问 API key env var（即你导出的那个变量的名字）和 Chat model，而不是 Base URL 和 Chat model name。

Ollama 的默认地址 http://localhost:11434 没有 /v1，这是正确的：ollama 后端使用 Ollama 自己的 API，而不是兼容 OpenAI 的 API。

接着，向导会向每个服务器发送一个简短的测试请求（Probing backends ...）。如果某个服务器没有响应，它会输出 Probe failed: … 并询问 Save config anyway? [N]；直接按回车则什么也不保存。成功时，它会输出 Config saved to …（后面是 ~/.cache/localmelo/config.toml 的路径），然后启动网关，地址为 http://127.0.0.1:8401。网关会一直在这个终端中运行。

启动网关

在第二个终端中检查网关，并通过它运行一个任务：

curl http://127.0.0.1:8401/v1/health
curl -X POST http://127.0.0.1:8401/v1/agent/run \
  -H "Content-Type: application/json" \
  -d '{"query": "What is 6*7?"}'

示例输出（具体数值会不同）：

{"status":"ok","uptime":12.3,"sessions":{"active":0,"busy":0,"max":50},"chat_backend":"ollama","embedding_backend":"none"}
{"result":"42","session_id":"a7e8f646ca2e"}

健康检查不会连接模型服务器，运行任务时才会。在浏览器中打开 http://127.0.0.1:8401/ 即可使用网页界面（playground）。

在第一个终端中按 Ctrl+C 停止网关。之后运行任务会使用保存的配置：

melo "What is 6*7?"

以后想跳过向导、直接启动网关时，运行 melo --serve。

交互式对话

不带任务运行命令，即可开始终端对话，并在多轮对话中使用同一个智能体：

melo
# Or use the exact model ID from an OpenAI-compatible server:
melo --base-url http://127.0.0.1:8500/v1 --chat-model YOUR_MODEL_ID

用 /help 查看命令，用 /exit 或 Ctrl-D 退出。melo --reconfigure 用来配置后端；加上 --serve 则会在配置完成后启动网关。

http://127.0.0.1:8401/ 上的网页工作区支持模型发现、独立的对话草稿、代码格式化、取消运行和响应式导航。连接到同一网关的浏览器客户端会同步对话状态，刷新页面也能恢复仍然有效的对话。会话不会在网关重启后保留，直接运行的命令行对话与网页对话相互独立。
