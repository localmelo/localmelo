架构

localmelo 的各部分如何协同工作：melo/ 中是智能体及其检查、记忆和工具，support/ 中是后端、网关和配置。

组件

每个组件目前做什么，以及代码在哪里。路径都相对于仓库根目录。

命令行

melo 命令。给出任务时，它以直接模式运行：创建一个智能体，运行这个任务，以文本或一行 JSON 输出结果，并用退出码表示运行是如何结束的。不带任务时，它会打开交互式终端对话；--serve 用来启动网关，--daemon 用来管理 macOS 后台服务。使用 --base-url 时，智能体直接连接该服务器，不读取配置文件。

关键文件：__main__.py。

网关

melo --serve 启动的 HTTP 服务器。它提供 HTTP API（/v1/health、/v1/agent/run、/v1/sessions），最多保留 50 个会话，每个会话都有一个根据配置文件创建的智能体。每个请求在运行前都要通过检查：任务的长度和会话 ID。在 / 上，它提供网页界面（playground），网页界面有自己的一套会话。网关没有身份验证，默认监听 127.0.0.1:8401。

关键文件：support/gateway/__init__.py、session.py、webapp.py、playground.py，以及用于 macOS 后台服务的 daemon.py。

MCP 服务器

通过 stdio 使用 Model Context Protocol 通信的本地服务器，列在 --mcp-config 指定的 JSON 文件中。第一次运行开始时，support/mcp 会启动每个服务器，列出它的工具，并以 mcp__<server>__<tool> 的名称把这些工具注册到工具注册表和执行器中。MCP 工具可以在直接模式和 Python API 中使用，网关会话中不能使用。

关键文件：support/mcp/config.py、client.py、provider.py，以及 melo/contracts/tools.py 中的工具提供方接口。

智能体

运行循环。每一步都会根据任务、工作记忆、召回的长期记忆和最新的反思构建提示词，向模型提供一组工具，发送一次规划请求，然后运行回复中的工具调用。如果回复只有文本、没有工具调用，它就是最终答案，运行以 completed 结束。在默认的 reflect 策略下，步骤按尝试分组，每次尝试最多 10 步；一次尝试没有得到答案就结束时，由反思决定是否开始下一次尝试。每次运行都以九种状态之一结束（在 Python API 中，被停止的交互式运行以 cancelled 结束），并返回一个 RunResult。模型请求失败时，如果重试可能成功，最多重试两次。

关键文件：melo/agent/agent.py、melo/agent/options.py（AgentOptions）、melo/agent/_chat.py（规划和反思请求、重试）、melo/schema.py（RunResult 和各项上限）。

检查器

在一次运行的各个边界进行检查：

  • 规划请求之前：提示词最多 100,000 个字符，本步提供的工具列表必须有效；
  • 规划请求之后：回复中的每个工具调用都要有名称和唯一的 ID；
  • 工具运行之前：shell_exec 会拒绝六种破坏性的命令模式；
  • 工具运行之后：超过 50,000 个字符的输出会被截断；
  • 写入记忆之前：限制写入的大小；
  • 在网关中：检查每个请求的任务和会话 ID。

规划请求前后的检查一旦失败，运行就以 failed 结束。被拒绝的工具调用不会运行：模型会把这次拒绝当作工具返回的错误。

关键文件：melo/checker/checker.py、validators.py、payloads.py。

执行器

按顺序运行一步中的工具调用。以下调用会被拒绝：本步没有提供的工具、参数不是 JSON 对象的调用，以及内置工具参数类型不对的调用；剩下的每个调用再交给检查器检查。设置了工作区根目录时，工作区策略接着解析文件工具的路径，并拒绝根目录之外的路径。设置了审批策略时，需要审批的工具的调用接着等待审批策略的决定；获准之后，如果设置了工作区根目录，文件路径会被重新解析，路径在等待期间发生了变化的调用会被拒绝。每个工具都有时间限制，从审批之后开始计时：shell_exec 30 秒，file_read 和 file_write 60 秒，MCP 工具使用其服务器的 timeout。没有工作区根目录时，python_exec 的代码在 localmelo 进程内运行，无法中断。拒绝、审批不通过、超时或出错都会作为工具的错误返回。

四个内置工具是 shell_exec、python_exec、file_read 和 file_write。直接模式和网关不给它们设置工作区根目录，所以文件工具可以访问你能访问的任何文件。在 Python API 中，AgentOptions(workspace_root=…) 会启用 policy.py：文件工具只能访问根目录内的文件；shell_exec 和 python_exec 在根目录中以子进程运行，但不受这个限制。只有带审批策略的运行才会审批。

关键文件：melo/executor/executor.py、builtins.py、policy.py、melo/contracts/approvals.py。

记忆

工作记忆保存一次运行或一个网关会话中的对话：最近 20 条消息，只在内存中。历史记录保存每个任务和每一步。长期记忆需要嵌入后端：它把步骤摘要和反思连同嵌入向量一起保存，并在每一步召回最接近的 5 条。历史记录和长期记忆默认留在内存中；开启持久化后，分别写入 history.db 和 long_term.db。工具注册表保存所有已注册的工具，以及检索模式使用的 BM25 索引。

关键文件：melo/memory/coordinator.py、short/（工作记忆）、history/、long/、tools/（工具注册表）、bm25.py。

记忆设计（计划中）：记忆设计页保留了维护者为记忆撰写的设计，其中部分内容尚未实现。

配置和向导

~/.cache/localmelo/config.toml 记录对话后端、嵌入后端及其设置。配置向导（melo --serve --reconfigure）会询问这些设置，向每个服务器发送测试请求，保存文件，然后启动网关。直接模式和网关都根据这个文件创建智能体。

关键文件：support/config.py、support/onboard.py、support/onboard_probe.py。

提供方

连接模型服务器的 HTTP 客户端：兼容 OpenAI 的对话接口（/chat/completions）、Ollama 自己的 /api/chat，以及兼容 OpenAI 的嵌入接口。它们实现 melo/contracts/providers.py 中的接口，应用对话请求超时，并把每个失败的请求报告为 ProviderError，同时说明重试是否可能成功。

关键文件：melo/contracts/providers.py、support/providers/llm/、support/providers/embedding/。

后端

每个后端键对应一个适配器：mlc、ollama、vllm 和 sglang 用于你自己运行的服务器，openai、anthropic、gemini 和 nvidia 用于云端 API。每个适配器检查配置文件中属于自己的表，并创建提供方。后端只负责连接：模型服务器由你自己启动和停止。

关键文件：support/backends/registry.py、base.py、local/、cloud/。

melo/sleep/、melo/memory/personalized/ 和 support/melo_serving/ 中的代码，智能体目前还没有使用。

边界

边界规则意义
melo/ 和 support/ melo/ 包含智能体以及提供方要实现的接口，不在模块级别导入 support/。唯一的桥梁是 Agent(config=…)：调用它时，它通过 support/backends 创建提供方。 智能体可以使用你自己创建的提供方运行（例如测试用的假提供方），新增后端也只需要修改 support/。
智能体和执行器 每一步只能运行本步提供的工具，每个调用都要先通过检查。这些检查只是防护措施，不是沙箱：工具以你的账户权限运行。 模型只能调用本步展示给它的工具，被拒绝的调用永远不会运行。
智能体和记忆 写入记忆要经过检查器的大小限制。只有配置了嵌入后端并且记忆开启时，才会写入长期记忆。 提示词和存储都不会无限增长。
后端和模型服务器 后端只连接一个地址。localmelo 不负责下载、启动或部署模型。 模型服务器始终由你掌控。

目前已有的功能

  • 直接模式：运行选项、九种运行状态、文本或 JSON 输出，以及固定的退出码。
  • 四个内置工具，以及本地 MCP 服务器提供的工具（在直接模式和 Python API 中）。
  • 网关：HTTP API、会话、网页界面，以及 macOS 后台服务。
  • 支持 Ollama、MLC LLM、vLLM、SGLang 和四个云端 API 的后端。
  • 工作记忆、历史记录和长期记忆；开启持久化后会保存到 SQLite。
