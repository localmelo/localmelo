localmelo 内部的调用和数据

批准每一步的只有你，或自动模式的复核，对话和后台任务都一样。你允许的事会保存为授权，重启后仍然有效。

  • 你和主对话交流。旁支对话能力相同，共享记忆，从第一条消息起就是如此。
  • 对话先判断这件事由谁来做。短的它自己做，就在它自己的运行里，用的是和后台任务相同的智能体、相同的检查和审批；长的交给一个任务，对话留着继续和你说话。这个判断不靠词表，也不靠步数：模型读你说的话，然后动手，或者说明为什么不做。
  • 对话工作时你发的话是一条补充：它在下一步读到。停止会结束这一轮；旁支对话可以同时做别的事。
  • 任务是单独的一次运行：你要求开任务，对话为长工作开任务，或对话把做着做着变长的工作剩下的部分交出去（它的回合就此结束，任务从它做过的和剩下的开始），定时事项也会按时启动。调度器按级别（P0 到 P5）和模型槽位给任务排序，再启动后台任务；后台任务的名字说明它为哪个对话工作。
  • 任务属于启动它的对话：进展和结果回到那里；旁支对话会给主对话留一份已完成工作的总结。
  • 对话可以查看后台任务的状态，也可以在它运行时给它发消息。后台任务向所属对话求助；只有对话会来问你。
  • 一个后台任务只运行一次：新的上下文、一项工作，然后保存结果。之后关于这项工作的事，不管是新的要求、没做完的部分、继续还是收尾，都交给新的后台任务，旧任务的记录作为背景带过去；旧任务不会再运行。
  • 对话启动的任务开始时带着你的原话、所属对话挑选的内容，以及一份上下文包：关于你、你的偏好和这个项目的笔记。

由检查器把关

后台任务快速完成一项工作。它自己没有长期记忆，遇到问题先问所属对话，只有对话才会来问你。

  • 它运行与对话的智能体相同的循环：规划一步，通过执行器运行工具，每次调用都要先过检查。
  • 它从所属对话拿到任务说明：任务的目标、你的原话、所属对话挑选的内容，以及一份上下文包，内容是关于你、你的偏好和这个项目的笔记，与任务匹配。
  • 遇到阻碍时，它向所属对话求助；对话会回答，或来问你。
  • 步数上限会让它停下；最后两步留给提交和汇报。
  • 它的每一步由你批准，或由自动模式的复核决定；自动模式下它只在自己的文件夹里写入。

localmelo 内部的调用和数据
发往模型服务器的请求
  • 终端和 App 通过同一个端点文件找到正在运行的网关，所以后启动的那个会用已在运行的网关。
  • 主对话在自己的运行里替你做事；任务按优先级交给调度器，结果以卡片的形式回到它那里。
  • 定时事项按时启动任务；每 30 分钟，check-in 告诉主对话什么做完了或在等你。
  • Worker 和对话运行同一个智能体；对话把记忆召回到每一轮里，worker 自己不保留记忆，开始时带一份来自所属对话的上下文包。

后台浏览器

打开浏览功能后，melo 可以在没有窗口的 Chrome 里读网页，并在网页上操作。选择一个方框可以跳到它的卡片。

智能体 调用浏览器工具 网关 启动并驱动 Chrome Chrome 没有窗口 · 自己的配置 控制台和 App 浏览器面板 · 实时画面
各部分之间的调用和数据
  • 浏览器工具的调用经网关到达 Chrome；网关启动它时没有窗口，从不来到你的应用前面。
  • 网关通过私有管道和 Chrome 通信，从不用网络端口，Chrome 使用 melo 自己的配置。
  • 控制台和 App 实时显示网页；画面只保存在内存里，并且只在浏览器面板打开时才会发送。
  • 接管把网页交给你，你可以自己登录；在你交还之前，melo 在它上面的步骤会等着。
  • Safari 的自动化窗口是另一种浏览器：它们会来到最前面，没有实时画面。

组件

每张卡片说明一个部分做什么；点击图中的方框可以打开卡片，卡片上的链接打开对应的参考页。

终端

melo 打开主对话；melo "task" 运行一个任务。

  • 打印答案或一行 JSON，并用退出码说明运行如何结束。
  • 运行命令和写文件之前先询问；文件工具只在当前文件夹内工作。
  • 通过 App 使用的同一个网关打开主对话；-u、-c、-r 和 --yolo 会保留终端自己的对话。
命令行参考（英文）

网关

melo serve：控制台、App 和 HTTP API 背后的本地服务器。

  • 在 /api 下提供控制台的 API v2，在 /v1 下提供 HTTP API。
  • 网关要求 bearer 令牌或浏览器会话，并且只监听回环地址。
  • 持有令牌者能以你的权限操作；同一用户的进程之间没有隔离。
API v2 参考（英文）

端点文件

~/.cache/localmelo/gateway/endpoint.json 指明正在运行的网关。

  • 网关启动时写入它，停止时删除它。
  • 终端和 App 都先读它，所以后启动的那个会用已在运行的网关。
  • 里面只有端口，没有凭据。
终端的主对话（英文）

对话

每个对话是一个会话，它的轮次在重启后仍然保留。

  • 每一轮在该对话自己的智能体上运行，一次一轮，并附上记忆为它召回的内容。
  • 控制台、App 和终端打开的是同一个主对话；旁支对话列在它下面，旁支对话结束或任务需要你时，它会显示一张卡片。
  • 对话先判断这件事由谁来做：短的在这一轮里自己做（文件、Python、网页和浏览器，每一步的审批都一样），长的交给任务。
  • 它工作时你发的话会作为补充加入这一轮，在下一步读到；停止会结束这一轮。
  • 你仍然可以要求开任务，每个对话都能启动任务；旁支对话结束工作时，主对话会读到一行说明，记忆会保留它的总结。
会话参考（英文）

调度器

为任务排序；打开闸门后，也为模型调用排序。

  • 带六个级别（从“现在”到“以后”，即 P0 到 P5）的任务队列，保存在网关的会话文件中。
  • 经批准后回来的任务按级别排队等待；没有轮次在运行的对话会把它的名额让给任务。
  • 可选的模型调用闸门（先到先得或按类别）会读取共享的 GPU 锁和电池状态。
调度器指南（英文）

定时事项

按时运行的任务，以及告诉你发生了什么的 check-in。

  • 在任一对话里说 每个工作日 8:30 给我总结日程：它保存你的整句话，并提供撤销。说 现在做一次，以后每天九点也做 时，它还会马上运行一次。
  • 每 30 秒检查一次，把到期的事项作为任务开始，绝不提前；电脑睡眠时错过的一次，醒来后只运行一次。
  • 事项的每次运行和你亲自交办的任务一样：可以浏览网页，实时画面显示在保存它的那个对话里，每次运行共用一个工作文件夹（删除事项时一并删除），那个对话会收到它如何结束的消息。审批方式不变。上一次运行还没结束时，下一次时间会被跳过，对话里会说一次；等了你一个多小时的运行，则在下一次时间到来时被结束，这一次的运行开始。删除事项时仍在进行的运行会在原处结束，文件夹在它之后删除。
  • 每 30 分钟，check-in 告诉主对话什么做完了或在等你；这一行由 melo 根据事实写成，不调用模型。
  • 提醒是只运行一次的事项：提醒我明天九点给导师发邮件 会显示它理解的日期，你点“提醒我”之前不会保存任何东西。
会重复的事项（英文）

Worker

没有对话窗口、在后台运行任务的会话。

  • 网关按优先级启动排队的任务，每次几个，各在所属对话的文件夹里。
  • melo worker 根据任务说明文件运行一个任务，返回 JSON 结果。
  • 控制台的 Workers 视图列出每一次运行。
  • Worker 自己没有长期记忆；它运行时，所属对话可以查看它的状态，也可以给它发消息。
  • 对话开始的 worker 只运行一次：结束以后它的记录作为背景保留，之后的工作交给新的 worker。
  • 它开始时带一份来自所属对话的上下文包，遇到阻碍时向该对话求助。
Worker 参考（英文）

智能体

运行循环：规划一步，运行它的工具，在两次尝试之间反思。对话的一轮和后台任务都是这个循环。

  • 每一步的请求包含任务、工作记忆、召回的记忆和最近一次反思。
  • 模型只能调用这一步提供的工具。
  • 由反思决定是否开始下一次尝试。
工作原理（英文）

检查器

在运行的每个边界做检查。

  • 检查每个计划、每个工具调用和每个工具结果。
  • 被拒绝的调用不会运行；模型会看到原因。
  • 发送、删除或发布之类的调用总会询问，并说明原因。
  • 在“自动”下，由审查而不是一次点击来决定每一步；被拦下的步骤会得到解释，“允许一次”只让那一步运行一次。
  • 你为某个对话允许的事会保存为授权。
检查的作用（英文）

授权

你为某个对话允许过的事，保存在一张表里。

  • 一项授权是一个工具、一个网站、工作区之外的一个文件夹，或另一个应用的窗口。
  • 这张表在网关的会话文件里，所以授权在重启后仍然有效。
  • 在主对话里允许的，在每个对话里都算；在旁支对话里允许的，只在那里算。
  • 设置 → 授权列出它们，收回立即生效。
授权指南（英文）

执行器

按顺序运行一步中的工具调用，并设有时限。

  • 内置工具：shell_exec、python_exec、file_read、file_write 和 list_files。
  • 按权限级别请求审批。
  • 在 macOS 上，worker 运行、保存的任务和“自动”下的步骤只能在自己的文件夹内写文件，“自动”下的步骤也碰不到 melo 自己的登录信息。
工具参考（英文）

工具：MCP 和浏览器

内置工具之外的更多工具。

  • --mcp PATH 中列出的本地 MCP 服务器以 stdio 进程运行。
  • 它们的工具名为 mcp__<server>__<tool>。
  • 打开浏览功能后，melo 在后台的 Chrome 或 Safari 的自动化窗口里读网页，并在网页上操作。没打开时，对话会说明一次，并告诉你怎么打开。
工具和 MCP 指南（英文）

后台浏览器

没有窗口的 Chrome，用来读网页并在网页上操作。

  • 需要你自己开启：设置 → 对话和文件夹 → 浏览器，或 /browser chrome。
  • 网关启动这台 Mac 上安装的 Chrome，没有界面，使用 melo 自己的配置。
  • 浏览器面板实时显示网页；接管让你自己登录。
  • 其他应用在点击之后打开的窗口，会先问你。
浏览指南（英文）

记忆

melo 在一次运行内和跨对话保留的内容。

  • 工作记忆：一次运行最近的消息，保存在内存中。
  • 关于你的笔记和所有对话的索引，召回时注明来源。
  • 历史记录和长期记忆，开启持久化后保存在 SQLite 中。
记忆概念（英文）

配置和设置

一个配置文件，以及会自己找到服务器的首次运行。

  • ~/.cache/localmelo/config.toml 指定对话和嵌入服务器。
  • 首次运行会查找模型服务器，并推荐找到的那个。
  • 之后用 melo setup 和 melo config 修改。
配置参考（英文）

提供方

与模型服务器通信的 HTTP 客户端。

  • OpenAI 兼容的对话、Ollama 的 /api/chat 和 OpenAI 兼容的嵌入。
  • 对每个请求应用对话请求超时。
模型服务器指南（英文）

模型服务器

后端连接你自己运行的服务器或云端 API。

  • oMLX（通过 vllm）、Ollama、MLC LLM、vLLM 和 SGLang。
  • OpenAI、Anthropic、Google 和 NVIDIA 的 API。
  • localmelo 自己不提供模型；在 Mac 上，首次运行可以在你同意一次后设置 melo_serve 和一个模型。
后端（英文）

边界

边界规则为什么重要
melo/ 和 support/melo/ 从不导入 support/；调用方构建提供方（providers_for(cfg)）并交给 Agent。智能体可以使用你自己构建的提供方运行，新增后端只改 support/。
智能体和执行器一步只运行它提供的工具，每个调用都先通过检查。被拒绝的调用从不运行。在“询问”下，检查是护栏，不是沙箱；在 macOS 的“自动”下，步骤还会在写入沙箱里运行。
智能体和记忆记忆写入要通过检查器的大小限制。提示和存储都保持在限定范围内。
后端和模型服务器后端只连接一个 URL。模型服务器始终由你掌控。
