后台任务快速完成一项工作。它自己没有长期记忆，遇到问题先问所属对话，只有对话才会来问你。

  • 它运行与对话的智能体相同的循环：规划一步，通过执行器运行工具，每次调用都要先过检查。
  • 它从所属对话拿到任务说明：任务的目标，以及一份包含你的原话和记忆条目的上下文包 计划中。
  • 步数上限会让它停下；最后两步留给提交和汇报。
  • 它的每一步由你批准，或由自动模式的复核决定；自动模式下它只在自己的文件夹里写入。

组件

每张卡片说明一个部分做什么；点击图中的方框可以打开卡片，卡片上的链接打开对应的参考页。

终端

melo 打开主对话；melo "task" 运行一个任务。

  • 打印答案或一行 JSON，并用退出码说明运行如何结束。
  • 运行命令和写文件之前先询问；文件工具只在当前文件夹内工作。
  • 通过 App 使用的同一个网关打开主对话；-u、-c、-r 和 --yolo 会保留终端自己的对话。
命令行参考

网关

melo serve：控制台、App 和 HTTP API 背后的本地服务器。

  • 在 /api 下提供控制台的 API v2，在 /v1 下提供 HTTP API。
  • 网关要求 bearer 令牌或浏览器会话，并且只监听回环地址。
  • 持有令牌者能以你的权限操作；同一用户的进程之间没有隔离。
API v2 参考

端点文件

~/.cache/localmelo/gateway/endpoint.json 指明正在运行的网关。

  • 网关启动时写入它，停止时删除它。
  • 终端和 App 都先读它，所以后启动的那个会用已在运行的网关。
  • 里面只有端口，没有凭据。
终端的主对话

对话

每个对话是一个会话，它的轮次在重启后仍然保留。

  • 每一轮在该对话自己的智能体上运行，一次一轮，并附上记忆为它召回的内容。
  • 控制台、App 和终端打开的是同一个主对话；旁支对话列在它下面，旁支对话结束或任务需要你时，它会显示一张卡片。
  • 主对话自己回答简短的问题，或按优先级把更大的工作作为任务开始。
会话参考

调度器

为任务排序；打开闸门后，也为模型调用排序。

  • 带六个级别（从“现在”到“以后”，即 P0 到 P5）的任务队列，保存在网关的会话文件中。
  • 经批准后回来的任务按级别排队等待；没有轮次在运行的对话会把它的名额让给任务。
  • 可选的模型调用闸门（先到先得或按类别）会读取共享的 GPU 锁和电池状态。
调度器指南

定时事项

按时运行的任务，以及告诉你发生了什么的 check-in。

  • 在主对话里说 every weekday at 8:30, brief me on my calendar；你点按 Save chore 之前不会保存任何东西。
  • 每 30 秒检查一次，把到期的事项作为任务开始，绝不提前；电脑睡眠时错过的一次，醒来后只运行一次。
  • 每 30 分钟，check-in 告诉主对话什么做完了或在等你；没有可说的就不调用模型。
  • 提醒是只运行一次的事项：提醒我明天九点给导师发邮件 会显示它理解的日期，你点“提醒我”之前不会保存任何东西。
会重复的事项

Worker

没有对话窗口、在后台运行任务的会话。

  • 网关按优先级启动排队的任务，每次几个，各在所属对话的文件夹里。
  • melo worker 根据任务说明文件运行一个任务，返回 JSON 结果。
  • 控制台的 Workers 视图列出每一次运行。
  • Worker 自己没有长期记忆；所属对话可以查看它的状态，也可以给它发消息。
Worker 参考

智能体

运行循环：规划一步，运行它的工具，在两次尝试之间反思。

  • 每一步的请求包含任务、工作记忆、召回的记忆和最近一次反思。
  • 模型只能调用这一步提供的工具。
  • 由反思决定是否开始下一次尝试。
工作原理

检查器

在运行的每个边界做检查。

  • 检查每个计划、每个工具调用和每个工具结果。
  • 被拒绝的调用不会运行；模型会看到原因。
  • 发送、删除或发布之类的调用总会询问，并说明原因。
  • 在“自动”下，由审查而不是一次点击来决定每一步；被拦下的步骤会得到解释，“允许一次”只让那一步运行一次。
检查的作用

执行器

按顺序运行一步中的工具调用，并设有时限。

  • 内置工具：shell_exec、python_exec、file_read、file_write 和 list_files。
  • 按权限级别请求审批。
  • 在 macOS 上，worker 运行、保存的任务和“自动”下的步骤只能在自己的文件夹内写文件，“自动”下的步骤也碰不到 melo 自己的登录信息。
工具参考

工具：MCP 和浏览器

内置工具之外的更多工具。

  • --mcp PATH 中列出的本地 MCP 服务器以 stdio 进程运行。
  • 它们的工具名为 mcp__<server>__<tool>。
  • 打开浏览功能后，melo 在 Safari 的自动化窗口里读网页。
工具和 MCP 指南

记忆

melo 在一次运行内和跨对话保留的内容。

  • 工作记忆：一次运行最近的消息，保存在内存中。
  • 关于你的笔记和所有对话的索引，召回时注明来源。
  • 历史记录和长期记忆，开启持久化后保存在 SQLite 中。
记忆概念

配置和设置

一个配置文件，以及会自己找到服务器的首次运行。

  • ~/.cache/localmelo/config.toml 指定对话和嵌入服务器。
  • 首次运行会查找模型服务器，并推荐找到的那个。
  • 之后用 melo setup 和 melo config 修改。
配置参考

提供方

与模型服务器通信的 HTTP 客户端。

  • OpenAI 兼容的对话、Ollama 的 /api/chat 和 OpenAI 兼容的嵌入。
  • 对每个请求应用对话请求超时。
模型服务器指南

模型服务器

后端连接你自己运行的服务器或云端 API。

  • oMLX（通过 vllm）、Ollama、MLC LLM、vLLM 和 SGLang。
  • OpenAI、Anthropic、Google 和 NVIDIA 的 API。
  • localmelo 从不下载、启动或提供模型。
后端

边界

边界规则为什么重要
melo/ 和 support/melo/ 在模块级别从不导入 support/；Agent(config=…) 是唯一的桥。智能体可以使用你自己构建的提供方运行，新增后端只改 support/。
智能体和执行器一步只运行它提供的工具，每个调用都先通过检查。被拒绝的调用从不运行。在“询问”下，检查是护栏，不是沙箱；在 macOS 的“自动”下，步骤还会在写入沙箱里运行。
智能体和记忆记忆写入要通过检查器的大小限制。提示和存储都保持在限定范围内。
后端和模型服务器后端只连接一个 URL。模型服务器始终由你掌控。
