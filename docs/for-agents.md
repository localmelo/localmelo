# localmelo for agents

Humans: start at the [README](https://github.com/localmelo/localmelo#readme) or the [website](https://localmelo.github.io/localmelo/).

## What it is

- A local agent: it runs one task with tools (shell, Python, files, MCP) and memory, on a model server the user runs (any OpenAI-compatible server, Ollama) or a cloud API. It never downloads, starts or serves models.
- Three surfaces: the `melo` CLI (a fixed exit code per run, and one JSON line with `--output-format json`), the Python `Agent` (experimental), an HTTP gateway on 127.0.0.1.
- Pre-alpha: CLI, HTTP API and Python API may change before v0.1.0.

## Rules (read before running anything)

- Tools run as the user with no sandbox: never on untrusted input or near data the user cannot lose. Pass `--builtins none` (or `--mcp-only`) when no built-in tool is needed. A direct run offers no `shell_exec` by default; `--builtins all` (or naming it) turns it on, and it then runs unapproved.
- Never expose the gateway: host `127.0.0.1`, `localhost` or `::1` only (check `--host` and the user's `[gateway] host`); no `0.0.0.0`, LAN IP, reverse proxy or Tailscale Serve. It has no authentication: whatever reaches the port runs `python_exec` and `file_write` as the user, unapproved, and makes the web workspace fetch any URL. `shell_exec` is not offered in `gateway` mode. Any other host only logs a warning and turns the Host/Origin guard off.
- Never edit the user's `~/.cache/localmelo/config.toml` or delete `~/.cache/localmelo/` (cleaning `~/.cache` deletes both). For tests or your own backend, run `melo` with a temporary `HOME`.
- No API keys in the config file; `api_key_env` holds the variable's name.
- Never run `--daemon install` in tests. Never run bare `melo` (no task) in a pty or terminal under the user's `HOME`: with no config it asks setup questions and writes `~/.cache/localmelo/config.toml`; it also writes `~/.cache/localmelo/cli/sessions.db`, `cli_history` and `logs/cli.log`. Without a TTY, bare `melo` exits 2 with three stderr lines, and `--serve` with no config exits 1 with one; neither asks anything. `--reconfigure` without a TTY reads the wizard's answers from stdin (EOF: `Setup cancelled.`, exit 0).

## Install

```bash
git clone https://github.com/localmelo/localmelo.git
cd localmelo                 # keep this name: the package is built from this directory
uv sync --extra gateway      # pip: python3 -m venv .venv && . .venv/bin/activate && pip install -e ".[gateway]"
uv run melo --help
```

- `melo` lands in `.venv/bin/`, not on PATH. Below, `melo` means `uv run melo` in the clone, `uv run --project CLONE melo` elsewhere, or `CLONE/.venv/bin/melo` (for background jobs; see Gotchas). Scripts: `uv run [--project CLONE] python SCRIPT.py` or `CLONE/.venv/bin/python SCRIPT.py`. Under a temporary `HOME` prefer the `.venv/bin/` paths: `uv run` keeps its cache in `$HOME/.cache/uv` and may resolve and download again.
- Python >= 3.11; the `gateway` extra (fastapi, uvicorn) is needed for `--serve`. A renamed clone or ZIP folder gives `ModuleNotFoundError: No module named 'localmelo'`.
- Commands: `melo`, `melo-retrieve` and `melo-procedures` (offline only). macOS tested; Linux untested; no Windows.

## Use it

### CLI, one task (best for scripts)

```bash
melo --base-url http://127.0.0.1:8000/v1 --chat-model MODEL \
  --output-format json --timeout 300 --builtins none -- "What is the capital of France?"
echo $?   # 0 completed; 1 crashed (JSON line) or no/invalid config (no JSON line); 2 other status (JSON line) or usage error (no JSON line)
```

- `--base-url` is used verbatim (include `/v1`): no API key, a 120 s chat request timeout unless `--request-timeout`; with a task, `--chat-model` defaults to `default`. The three `[agent]` context-accounting keys still apply. Cloud APIs need the config file.
- oMLX (Apple silicon, macOS 15+): `omlx serve --model-dir DIR --port 8000` (a port saved in oMLX's settings.json wins when `--port` is left out; each subfolder of DIR with a `config.json` is a model; its folder name, or an alias set in oMLX, is the model id), then `--base-url http://127.0.0.1:8000/v1 --chat-model ID`; in the config file it is the `vllm` backend. oMLX must accept requests without an API key (no `--api-key`, no key from its admin page or `OMLX_API_KEY`, or "Allow inference without API key" on): localmelo sends none to local servers, and HTTP 401 means a key is set.
- Without `--base-url`: the config file; `--chat-model` and `--request-timeout` override it for the run. No config: exit 1, `No backend configured`.
- Drop `--builtins none` to give the model the mode's built-ins: `file_read`, `file_write` and `python_exec` in direct mode. `--builtins all` adds `shell_exec`. Quote the task after `--`; legacy task parsing and abbreviations are unchanged.
- Context accounting: `[agent] context_window`, `output_reserve`, `safety_margin` or matching `--context-window`, `--output-reserve`, `--safety-margin` flags (per-key overrides) enable telemetry when all resolve to positive integers and window > reserve + margin. Direct, interactive and console; not legacy `/v1`. JSON and `context_budget` events report a versioned estimate and measured prompt tokens per planning/reflection attempt. Missing/zero usage resets calibration; estimates and image allowance are not bounds. Over-budget requests are fitted on a copy, or end `context_budget_exceeded`; one classified context-overflow retry uses a strictly smaller request without rerunning tools. Output reserve is not enforced as a generation cap; see [configuration](reference/configuration.md#context-accounting).
- Direct-mode flags (first value is the default):
  - `--workspace DIR` (the folder the run works in: file tools stay inside it, `shell_exec` and `python_exec` start there; default the current folder; `~` is expanded, a path that is not a folder exits 2 with `melo: --workspace: not a directory: DIR`); `--max-steps N` (30 planning steps); `--attempt-policy reflect|none` (`reflect`: attempts of up to 10 steps, at most 5, a reflection between); `--reflection-gate flags|utility`; `--tool-exposure retrieve|all`.
  - `--builtins all|none|LIST` (comma list of `file_read,file_write,python_exec,shell_exec`; without it a direct run gets the first three, and `all` or `shell_exec` adds the shell); `--mcp-config PATH` (stdio MCP servers); `--mcp-only` = `--builtins none --tool-exposure all` (needs `--mcp-config`; do not also pass `--builtins` or `--tool-exposure`).
  - `--memory on|off` (long-term memory); `--memory-dir DIR` (save memory as SQLite); `--embedding-base-url URL`, `--embedding-model NAME` (embeddings for a `--base-url` run).
  - `--timeout S` (run wall clock; none); `--request-timeout S` (per chat request; `request_timeout_s`, else 120, 300 for `ollama`); `--output-format text|json`.
  - `--reasoning legacy|drop|replay|compress|compress+replay` (`legacy`: unchanged wire; `drop`: never send reasoning; `replay`: send assistant turns' reasoning under one key, by default only the current task's turns, earlier ones not; `compress`: send none, ask for a `<note>` before each tool call, keep notes, drafts and an attempt digest in a RAM-only store, and recall them at start/attempt/step; `compress+replay`: both); `--reasoning-field auto|reasoning_content|reasoning` (needed for `replay` and `compress+replay` with `--base-url`; `auto` follows the last reply's key; also accepted in the interactive UI, but never with native Ollama); `--replay-turns N` (newest N assistant turns with reasoning; inert outside `replay` and `compress+replay`); `--note-writer auto|heuristic` (`auto`: the model's `<note>`, else the heuristic; accepted and inert outside the compress modes); `--retriever auto|off|bm25|llm|embedding`, `--recall-at start,attempt,step,tool`, `--recall-k 1..10`, `--recall-kinds note,draft,thought,digest,reflection,long`, `--recall-placement tool|message`, `--recall-min-score 0..1`, `--retrieval-extra-body JSON` (R5: `auto` = embedding if configured, else llm at start/attempt and bm25 at step/tool; triggers default to start,attempt,step; tool is never on unless named; the block budgets are 9,500/turn, 12,000 live, 4,000 boundary; legacy refuses every one of these flags). `replay` caps one turn at 40,000 chars (skipped and counted); a backend with `requires_reasoning_replay = true` never cuts it, replays every assistant turn in the window (the task scope and `--replay-turns` do not apply), keeps the final answer's thinking with `record_answers`, refuses `drop`, and runs `compress` as `compress+replay` (the JSON reports that). The compress modes recall their notes, drafts and earlier thinking at start, attempt and step; see `--retriever`/`--recall-*` above.
  - `--progress auto|off` (`auto`: a progress line on stderr, `\r\x1b[2K` redraws, erased before the result, only when stderr is a TTY, `TERM` is not `dumb` and the output is text; with JSON output or no TTY nothing is drawn and the run is unchanged; not drawn while melo is a background job, `tcgetpgrp(2) != getpgrp()`; cut to the width with East Asian Ambiguous characters counted 2 cells when the locale (`LC_ALL`, `LC_CTYPE`, `LANG`) starts with `zh`, `ja` or `ko`); `--routine NAME` (procedural routine; blank is a usage error). Past-run facts on the line need `LOCALMELO_PERSIST_MEMORY=1` or `--memory-dir`; a similar match's facts follow `like <routine title>:` (or `like a similar task:` when the event names no routine), never `last time`; a `shell_exec` command sent as an argv array (a list of strings, which the tool refuses) is labelled by its words (`shlex.join`), not by its JSON.

Other modes:

- Attempt digests skip headings in the task line; `verified` requires a passing test runner or a check referencing a previously written file. A failed last check removes verification.

- Compress-mode heuristic notes extract up to 12 keyed facts from visible replies without a note block. Questions, plans and negated/cancelled statements are not positive facts; CJK-only keys are not extracted. Matching uses a unique best source and leaves ties or conflicts unsourced. Self-work frames are filtered unless they carry a keyed content clause; completed outcome-admitted digests are exempt. See [memory](concepts/memory.md#reasoning-notes).
- `melo ""`: the plain conversation loop on stdin (`/help`, `/exit` or `/quit`, Ctrl-D). Takes `--base-url`, `--chat-model` and `--builtins`; exits 0 even if every turn failed. Do not parse its output.
- `melo` with no task, no `--serve`, no `--daemon`: the interactive UI (prompt_toolkit, inline). Needs stdin and stdout TTYs and `TERM` not `dumb`, else exit 2. Backend, first that applies: `--reconfigure` (wizard); `--base-url URL` (model: `--chat-model`, else the first id from `GET URL/models` without `embed`/`rerank`, the list's first id when every id is one, else `default` with a warning under the banner when the list cannot be read or is empty; a URL without `/v1` is listed at `URL/v1/models` and, when that answers, chatted with at `URL/v1`; with no config file asks `Save URL · MODEL as the default backend? [Y/n]`); the config (no check before the UI; one `GET /models` after the banner, warning only); no config: `Model server URL [..]:` (prefilled from `GET /v1/models` on 127.0.0.1 ports 8000, 8400, 11434, 30000; `LOCALMELO_DETECT_URLS`, comma-separated, replaces them, empty turns it off) and `Model [N]:`, then when the list holds an embedding model other than the chat model `Use MODEL for long-term memory? [Y/n]:` (Qwen3-Embedding first; `y` proves it with one `POST /v1/embeddings` and saves the chat backend's `embedding_url`/`embedding_model`, `n`/a failed probe sets `"none"`; with no candidate one hint line, and one `GET /api/version` still tells Ollama apart), saves `chat_backend = "ollama"` with `[ollama] chat_url`/`chat_model` when the server answers `GET /api/version` like Ollama, else `chat_backend = "vllm"` with `[vllm] chat_url`/`chat_model`, and otherwise `embedding_backend = "none"`; failure: `[r]etry, [s]tart anyway, [q]uit [r]:`. Ctrl-D at a question: exit 0; Ctrl+C: 130. Takes `-c`/`--continue`, `-r`/`--resume [ID|TITLE]`, `--workspace DIR`, `--yolo` (no approvals), `--max-steps`, `--attempt-policy`, `--reflection-gate`, `--builtins`, `--memory`, `--memory-dir`, `--request-timeout`, `--reasoning`, `--reasoning-field`, `--replay-turns`, `--note-writer`, `--retriever`, `--recall-*`, `--retrieval-extra-body`, `--embedding-*`; explicit flags win over `[agent]`/`[retrieval]` defaults. `--base-url` ignores those defaults. Takes `--mcp-config FILE` (else the config's top-level `mcp_config`; a bad file: `melo: error: …`, exit 2), `--mcp-only` (needs `--mcp-config`). Refuses (exit 2) `--tool-exposure`, `--timeout`, `--output-format`, `--progress`, `--routine`, `--keep-decision-text`, `--host`, `--port`. Commands: `/help`, `/new` (`/clear`), `/verbose [on|off]` and `/thinking [on|off]` (flip when blank), `/expand [turn.call]` (a call's whole output, ≤ 200 lines then the rest's count), `/progress` (the latest `run.progress` in full), `/approvals [ask|auto|deny|forget [tool]]` (the mode and grants), `/status` (model, server and reachability, workspace, session, approvals, tools, memory, limits, files, version), `/mcp` (servers, tools, command lines, the file's source; why MCP is off), `/retry` (undo the newest turn and run it again), `/model [NAME|N]` (lists; switches only to a listed id or number 1..N, else `✗ URL lists no model named 'x'. /model lists them.`, nothing saved; with no list available, switches anyway with a warning), `/backend [URL]` (switches server, saved as `ollama` when it answers `GET /api/version` like Ollama, else `vllm`; keeps the config's embedding, `request_timeout_s`, `extra_body`), `/exit` (`/quit`); `/model` and `/backend` save the choice, except in a `--base-url` session that was not saved. A turn draws the model's thinking (3 rows; 40 with `/verbose`, none with `/thinking off`), intermediate and held text, notices and reflections in scrollback; its live rows show `run.progress` facts (step, attempt, phase, tests, time), the running tool, and on a first turn `format_past`'s past runs. A draft that starts with a space is a message. A turn that could not run puts its message back in the input box. Approval panel before `shell_exec`/`python_exec`/`file_write` (a `file_write` over an existing file shows a diff with `+a −b lines`): keys `1` once, `2` the tool for the session, `3` deny with a reason; no letters; keys ignored 0.4 s after it opens. Esc stops a turn (`cancelled`, cause `user_stop`). `shell_exec`/`python_exec` limit 600 s. Exit 0 on `/exit`, Ctrl+D, Ctrl+C twice; SIGTERM/SIGHUP: exit by the signal. Not for scripts: use direct mode.

- `melo --serve [--host H] [--port P] [--allow-unconfigured]` (`--allow-unconfigured` starts the gateway without a config file or when `config.toml` has validation errors, so `/api/health` and `/api/settings` can configure it; refused without `--serve` or with `--reconfigure`), `melo --reconfigure` (the wizard, then the UI; with `--serve`, then the gateway; without a TTY it reads answers from stdin, then exits 0 unless `--serve`; with `--base-url` and no task: exit 2), `melo --daemon install|uninstall|status` (macOS launchd). Direct-mode flags with `--serve`, or in `melo ""` except `--builtins`, are usage errors (exit 2), so are `--base-url`/`--chat-model` with `--serve`/`--daemon`, and `--yolo` with a task, `--serve` or `--daemon`.
- Worker history: direct `--save-session [TITLE] -- TASK` records one `kind=worker` session in the CLI file; `--parent-run ID` requires it. `--import-session dsh-jsonl FILE [--title TITLE]` imports once by content hash; unknown/invalid lines are counted. `GET /api/sessions?kind=worker` supports `status`, `source`, `parent_run`, `cursor`; worker detail and `turns?events=true` are read-only. Workers never appear in chat pickers. The workspace defaults to cwd; worker `session.tokens` is total tokens, and `meta.usage` is the full map. SQLite may create WAL/SHM sidecars on reads. Redaction is pattern-based; recognized sensitive-file reads are omitted, but arbitrary printed secrets may persist. Thinking uses the existing retention rule.
- The web workspace's `#/workers` lists worker history with server-side filters and cursor paging; `#/workers/<id>` opens a read-only snapshot with explicit refresh, not SSE. It does not send, approve or change grants. Worker details remain separate from chat drafts. Worker detail `tokens` is null when no turn has integer completion tokens; chat-only details and submission lookup return 404 for worker-only IDs. See the [console guide](guides/web-console.md) and [API v2 reference](reference/api-v2.md).
- Reasoning in sessions: the current process's mode and RAM-only notes/drafts survive `/model`/`/backend`. Resume keeps the process's mode, not an old outcome's config. A replay-required provider refuses `drop` without changing the old Agent/backend/MCP state. Session replay scope is `window`; pairs restore no old thinking, window restores retained redacted thinking; explicit non-replay modes strip legacy inline copies from sends only. Neither resume path rebuilds the RAM-only NoteStore from `turns.note`. Console sessions use configured reasoning (default `legacy`) and keep `mode="gateway"`; legacy `/v1` is unchanged. No `/reasoning` command or replay-scope flag.
- Saved terminal sessions: `-c` resumes the newest eligible chat in the current workspace, `-r REF` resolves exact ID/prefix (at least 4 characters)/case-insensitive title then searches; no value opens the picker. `/sessions [filter]` and `/resume [id|title]` are idle-only. Picker: 50 finished, non-undone chat sessions; filter debounce 150 ms, Tab folder/all-folders, arrows/Enter select, Esc/Ctrl+D close with draft intact. Empty startup selection starts new lazily; unknown startup ref exits 2. Resume retains current workspace/model and `/verbose`/`/thinking`, clears grants, prints the last 3 turns and `last_resume` counts; startup selection/picker precedes the banner, which names the chosen chat as resumed; `[sessions] resume_mode = "pairs"` (default) or `"window"`, invalid value warns/falls back only in the UI. Before sending, cross-window changes reload memory and metadata; busy/deleted sessions restore drafts. `/retry` preserves stored typed text; `/expand` pages persisted events after resume. Exit prints `melo -r ID` for a saved session with turns. `-c` + `-r`, or either with a task/`--serve`/`--daemon`, exits 2.
- Terminal session tools: `/title [text]` shows/sets 1–200 chars, pending until lazy first-turn creation; `/new` and successful resume clear the pending title. `/undo` is idle-only: forget the newest finished turn, keep its typed text in ↑ history, never roll files back; another window's active turn blocks it. A committed undo settles and prints success even after Esc; its busy hint asks you to wait. `/retry` re-runs an undone newest turn without undoing the previous live turn. `/usage` includes undone rows/work; missing/running counters are `?` and partial totals `+?`; below 72 columns, labeled rows wrap without ellipsizing counts. `/memory` reads a copied working window and `last_resume` (pairs/fallback vs checkpoint tail), with cleaned/redacted rows and backend label; no model request or memory write. `/title`, `/usage`, `/memory` and `/copy` run during a turn, except title writes during session switching. `/copy [turn]` reads stored redacted Markdown without thinking, preserving code indentation/trailing newlines via `split_thinking(..., strip_answer=False)` (all existing callers retain the stripped default); explicit selection reads one row, default selection pages backward; default newest finished/non-undone, explicit undone allowed; labels/empty/running answers refused. Local macOS: absolute `/usr/bin/pbcopy`, 2 s timeout; SSH/other platforms/native failure: base64 OSC 52 request, not confirmed success. Temporary HOME does not isolate the OS clipboard: tests must fake native copying or capture OSC 52 in a synthetic PTY.
- Wizard: every prompt defaults to the config's value (embedding: a saved backend, else a working setup's own; with none saved, the chat server's listed embedding models append as options 6+ and the first is the default, while `5` stays `None`); a chosen detected model asks no URL/model question. A failed chat check asks `[r]etry, [s]ave anyway, [N]o [N]:`; a failed embedding check saves with `embedding_backend = "none"`. Never asks for an API key for a local server.

### Python API (experimental)

```python
import asyncio
from localmelo import Agent, AgentOptions
from localmelo.support.providers.llm.openai_compat import OpenAICompatLLM

async def main() -> None:
    llm = OpenAICompatLLM(base_url="http://127.0.0.1:8000/v1", model="MODEL")  # include /v1
    agent = Agent(llm=llm, options=AgentOptions(builtins=[], timeout_s=300))  # builtins=[]: no tools
    try:
        r = await agent.run_task("What is the capital of France?")
        print(r.status, r.result or r.error)
    finally:
        await agent.close()  # there is no `async with` and no aclose()

asyncio.run(main())
```

- `localmelo` also exports `AgentEvent`, `Message`, `RunResult`, `ToolCall`, `ToolDef`, `ToolResult`; event and approval types are in `localmelo.melo.contracts`, `ProviderError` only in `localmelo.melo.contracts.providers`.
- `Agent(config=None, *, llm=None, embedding=None, options=None, tool_providers=())`; `llm=` wins; neither raises `TypeError`. From the config file: `from localmelo.support.config import load`; `cfg = load(); cfg.validate_or_raise(); Agent(config=cfg)`.
- `OpenAICompatLLM(base_url, model, api_key=None, timeout=120.0, *, extra_body=None, extra_body_by_kind=None)`: `api_key` goes out as a Bearer token; misspelled keywords are silently ignored; `timeout=None` means no timeout at all.
- `AgentOptions` (frozen; bad values raise `ValueError`): `max_steps=30`, `attempt_policy="reflect"`, `steps_per_attempt=10`, `max_attempts=5`, `reflection_gate="flags"`, `tool_exposure="retrieve"`, `builtins=None` (the mode's default: `file_read`, `file_write` and `python_exec` for `python`, `direct` and `gateway`; all four for `interactive`), `mode="python"` (`direct`, `interactive`, `gateway` or `python`; only `interactive` offers `shell_exec` by default, and naming it in `builtins` lets a `direct` or `python` run use it), `memory=True`, `memory_dir=None`, `timeout_s=None`, `workspace_root=None`, `record_answers=False`, `tool_timeout_s=None` (needs `workspace_root`), `tool_env=None` (a mapping of extra variables for the `shell_exec`/`python_exec` children), `reasoning="legacy"`, `replay_turns=None`, `replay_scope="task"` (API-only; `"window"` replays earlier tasks' turns), `note_writer="auto"`, `retriever="auto"`, `recall_at=None`, `recall_k=3`, `recall_kinds=None`, `recall_placement="tool"`, `recall_min_score=0.35`, `admit_on_outcome=False`, `keep_decision_text=False`.
- `await agent.run_task(query, *, on_event=None, approval=None, observe=None, progress=False, routine=None) -> RunResult`. `await agent.run(query) -> str`: the result, or `[STATUS] ERROR` when it is empty.
- `on_event`: a plain sync callable taking an `AgentEvent` (`type`, `run_id`, `seq`, `ts`, `data`); `async def` raises `TypeError`; never block in it. Types: `run.started`, `step.started`, `assistant.message`, `tool.started`, `tool.finished`, `note` (in the compress modes), `recall`, `notice`, `reflection.started`, `reflection`, `run.progress` (only with `progress=True`), `run.finished` (`RunResult(**event.data["result"])`).
- `observe`: a sink like `on_event` that does not make the run interactive (a cancelled run ends `crashed`); not both. `progress=True` with a sink adds `run.progress` (level 0 facts, or level 1 with past runs' facts and named steps; no percent in this release). `routine="NAME"`: one procedural routine in any folder, whatever the wording; blank raises `ValueError`. `localmelo.support.progress_line.format_past(payload, width)` gives that line's past-facts-and-items segment alone (same wording and widths; empty below level 1 or when there is nothing).
- `approval`: an object with `async def decide(request: ApprovalRequest) -> ApprovalDecision` (e.g. `ApprovalDecision(allow=False, reason="...")`; `AllowAllPolicy`, `DenyAllPolicy` exist), asked before a built-in or provided tool whose permission tier is not `read` (`write`, `exec`, `network`) and before any tool explicitly marked (MCP `require_approval`, `ProvidedTool.requires_approval=True`, a custom tool's `register` mark); `request.tier` names the tier, and a raise denies. Without a policy every tool runs.
- `workspace_root=DIR`: `file_read` and `file_write` stay inside DIR; `shell_exec` and `python_exec` start in DIR as child processes but can reach any path.
- Stop a run: cancel the task awaiting `run_task` (it re-raises `CancelledError`). With `on_event` or `approval` the run ends `cancelled`, its result only in `run.finished`; with neither (`observe` does not count) it ends `crashed`, no result.
- MCP: `tool_providers=[McpToolProvider(load_mcp_config("mcp.json"))]` (`localmelo.support.mcp`).
- Sessions (experimental, `localmelo.support.sessions`): conversations in SQLite that survive a restart. The agent needs `record_answers=True` and a `workspace_root`, and `await agent.start()` first. `store = SessionStore(PATH, writer="cli")` (or `"gateway"`; a file belongs to one writer); `runner = SessionRunner(agent, store, None, new_session=NewSession(workspace=agent.workspace_root))`; `await runner.run_turn(text)` returns a `RunResult`; keep `runner.session_id`. Later, with a fresh agent: `SessionRunner(agent, store, session_id)`, `await runner.resume()`. Close the runner, then the agent, then `await store.aclose()`. `SessionRunner(..., progress=True)` asks each turn's run for `run.progress` and stores it (kept across `replace_agent`); without it a session turn reports none. The interactive UI asks for them. `run_turn`/`start_turn` take `routine="NAME"` and pass it to `run_task` only when given. `build_session_agent(...)` returns a started Agent with the session's options; its `wrap_llm`/`wrap_embedding` wrap the providers before the Agent's `Chat` is made, after non-replay OpenAI-compatible fields are cleared. With options omitted it reads configured agent/retrieval defaults; explicit options win. It sets `replay_scope="window"` and retains the surface's tool mode; only legacy without hooks keeps the original config construction path. See [sessions.md](reference/sessions.md).

### HTTP gateway

The gateway reads only `~/.cache/localmelo/config.toml`. For your own backend or a test, give it a temporary `HOME` with its own file (here for any OpenAI-compatible server):

```bash
T=$(mktemp -d); mkdir -p "$T/.cache/localmelo"
cat > "$T/.cache/localmelo/config.toml" <<'EOF'
chat_backend = "vllm"
embedding_backend = "none"

[vllm]
chat_url = "http://127.0.0.1:8000/v1"
chat_model = "MODEL"
EOF
```

## Output and results

The CLI example's JSON line (field order fixed; `RunResult.to_dict()` is the same without `localmelo_version`):

```json
{"task_id": "ee8befecca3b4fd4bae6499fa0c73704", "status": "completed", "result": "Paris is the capital of France.", "error": "", "steps": 1, "attempts": 1, "n_llm": 1, "n_main": 0, "n_aux": 1, "n_tool": 0, "llm_errors": 0, "usage": {"prompt_tokens": 120, "completion_tokens": 12, "total_tokens": 132}, "duration_s": 0.015203958842903376, "config": {"max_steps": 30, ..., "tools": []}, "localmelo_version": "<git describe or version>"}
```

- `n_llm` requests answered, `llm_errors` failed attempts (sum = requests sent), `n_main` with tools offered, `n_aux` without (reflections and recall's retrieve requests included), `n_tool` tool calls (refused included). `config`: the `AgentOptions` fields except `workspace_root`, `record_answers`, `tool_timeout_s`, `tool_env` and `replay_scope` (`memory_dir` as resolved, `builtins` as registered), and `tools`, every registered tool's name (not only those a step offered). Outside `legacy`, `config` adds `reasoning`, `replay_turns`, `note_writer`, `retriever`, `retriever_effective`, `recall_at`, `recall_k`, `recall_kinds`, `recall_placement` and `recall_min_score`, `usage` adds `reasoning_chars` and any `cached_tokens`/`reasoning_tokens` the server reported, and `memory_stats` holds `replayed_chars`, `replay_skipped`, `replay_stripped`, the note counters `notes`, `notes_model`, `notes_heuristic`, `note_chars`, `drafts`, `drafts_written`, `candidates`, `remember_model`, `remember_heuristic`, `candidates_refused`, `redactions`, `rehearsed` (`{"restated", "acted", "cited"}`), `digests`, the recall counters `recalls`, `recalls_by_trigger`, `recall_hits`, `recall_chars`, `recall_ms`, `recall_fallbacks`, `recall_skipped`, `recall_refused`, `recall_empty`, `aux_retrieve_calls`, `retrieve_errors`, `retrieve_prompt_tokens`, `retrieve_completion_tokens`, `thought_chunks`, and `recall_log` (zero or empty in modes that use none of them). A `legacy` line has none of them and is byte-identical to before. `localmelo_version`: `git describe` of the checkout, else the installed version, else `unknown`.
- Text mode: `result` on stdout (tool writes to fd 1 go to stderr); a non-completed run adds `melo: run ended with status STATUS: ERROR` on stderr and may still print a best-effort result.
- Statuses, exit 2 unless noted:
  - `completed` (exit 0). `timeout`: `Timed out after N s`. `budget_exhausted`: `Max steps reached` or `Max attempts reached`.
  - `failed`: a check refused, or 2 empty replies in a row. `gate_stopped`: the reflection stopped the run with budget left. `stuck` (`--attempt-policy none` only): the same calls or errors repeated.
  - `provider_error`: a chat request still failed after its retries (network errors, timeouts and HTTP 429/502/503/504 are retried twice, after 1 s, then 4 s more), or an embedding request failed (never retried). `setup_error`: an MCP server or tool provider failed to start; permanent for that `Agent`.
  - `crashed` (exit 1, or the signal's code below): an unexpected exception or a signal (`Cancelled by SIGTERM` or `Cancelled by SIGHUP`; SIGINT records `CancelledError` and prints a traceback on stderr). `cancelled`: Python runs only.
- Other exit codes (no JSON line): 2 usage error, bad `--mcp-config`, `--memory-dir` or `LOCALMELO_THINKING_RETENTION_DAYS`; 1 no backend, invalid config or TOML, unset cloud key variable, the wizard needed without a TTY; 3 gateway port in use; 143, 129, 130 for SIGTERM, SIGHUP, SIGINT (the task record is saved as `crashed`); bare `melo`: 2 no TTY, `TERM=dumb` or `--workspace` not a directory, 1 its session file, agent start or log folder failed.

## Configuration

- File: `~/.cache/localmelo/config.toml`, fixed (no flag or env var; set `HOME` to isolate). Missing file = not configured.
- Top level, before any `[table]`: `chat_backend` (`mlc`, `ollama`, `vllm`, `sglang`, `openai`, `anthropic`, `gemini`, `nvidia`) and `embedding_backend` (`mlc`, `ollama`, `vllm`, `sglang`, `none`), both required; optional `request_timeout_s` (unquoted number > 0).
- Local table (`[mlc]`, `[ollama]`, `[vllm]`, `[sglang]`): `chat_url`, `chat_model`, `embedding_url`, `embedding_model`, `extra_body` (a table merged into every chat request), and the reasoning keys `reasoning_field` (`""`, `auto`, `reasoning_content` or `reasoning`; `[ollama]` takes `""`, `auto` or `thinking` instead) and `requires_reasoning_replay` (`false`). `mlc`, `vllm`, `sglang` add a missing `/v1`; `ollama` chat uses native `/api/chat`. `vllm` fits any OpenAI-compatible server.
- Cloud table (`[openai]`, `[anthropic]`, `[gemini]`, `[nvidia]`): `api_key_env` (the NAME of the env var holding the key; export it where `melo` runs), `chat_model`, `base_url` (used as given), `extra_body`, and the same two reasoning keys. No cloud embeddings.
- `[agent]`: `reasoning` (`legacy`, `drop`, `replay`, `compress` or `compress+replay`), `replay_turns` (an int >= 1, or omit), `note_writer` (`auto` or `heuristic`; omit for `auto`) and `tool_env` (extra inherited names, default `[]`). Direct/UI explicit flags win; console sessions honor the saved mode, defaulting to `legacy`; `/v1` remains unchanged. A `--base-url` run/session ignores these defaults.
- `[agent] tool_env = ["SSH_AUTH_SOCK", "HTTPS_PROXY"]`: portable ASCII names only (`[A-Za-z_][A-Za-z0-9_]*`), no assignments; missing variables skipped. Resolve present values for shell/Python children, save names only, omit values from run config; no MCP env change. These grant SSH-agent access or expose proxy credentials; tools can print/transmit received values. Never add names without the user's need/approval. API callers may pass an explicit mapping instead.
- `[retrieval]`: `retriever`, `recall_at` (a list), `k`, `kinds` (a list), `placement` and `min_score`. Direct/UI flags win over matching keys; console sessions use them too. The table is accepted and inert in `legacy`. A bad value is a configuration error (exit 1).
- `[gateway]`: `host` (`127.0.0.1`), `port` (`8401`), `workspace` (`""`, default `~/localmelo-workspace` in the console; written only when set). A configured workspace must be absolute or `~/` and must not resolve to `/` or home. `--host` and `--port` override them for one run. `config.save()` writes via a temporary file and `os.replace`.
- `[scheduler]`: `policy` (`off`, `fcfs` or `class`; default `off`), `n_srv` (`8`), `r_f` (`1`; forced to 0 when `n_srv <= 2`), `n_fg` (`1`), `call_log` (`true`), `call_log_dir` (`""`, meaning `~/.cache/localmelo/scheduler`), `gpu_lock_file` (`""`; a path to the shared GPU lock, empty means no lock reader), `lock_self` (`""`; exact holder or `holder:run`), `lock_gate` (`record` or `wait`; default `record`). The web workspace and the gateway console read it; direct runs and the CLI are ungated.
- Errors exit 1: `Configuration errors:` on stderr, or for invalid TOML a raw `TOMLDecodeError` traceback.
- `LOCALMELO_PERSIST_MEMORY` (any non-empty value, `0` included) saves memory as SQLite in `LOCALMELO_MEMORY_DIR` (default `~/.cache/localmelo/memory`; `~` not expanded).
- `LOCALMELO_THINKING_RETENTION_DAYS` (default 30; a number above 0, such as `7` or `0.5`): days of model reasoning kept in `history.db` and `sessions.db`. Any other value: exit 2 with one line before the run.
- Every chat request a run sends carries the header `X-Localmelo-Call-Kind`: `plan`, `reflect`, `estimate`, or `retrieve` for the llm retriever (as does `melo-retrieve`); embedding requests and the setup wizard's probe carry none.

## Tools and MCP

- `shell_exec(command)`: stdin `/dev/null`; env = `PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `TERM`, `LANG`, every `LC_*`, `TMPDIR` plus `AgentOptions.tool_env` (nothing else is inherited); process group killed after 30 s. Not offered by default in `direct`, `python` or `gateway` mode; `--builtins all`, `--builtins shell_exec` or `AgentOptions(builtins={"shell_exec"})` names it in `direct` or `python` mode, and it then runs (an approval policy, if the run has one, still asks). `gateway` refuses it even when named. The interactive UI offers it and asks.
- `python_exec(code)`: a child Python (`sys.executable -c`, a fixed wrapper) with the same env as `shell_exec`, the code on stdin (a pipe; fd 0 is then `/dev/null`, so `input()` gets EOF, and the code is not in argv), in the current directory (or the workspace root); its process group is killed at the tool's limit (60 s by default) or on cancellation; `sys.exit()` ends only the child; a non-zero exit fails with `Python exited with code <n>`, then the last 4,000 characters of its output.
- `file_read(path)`: any file the user can read. `file_write(path, content)`: creates or replaces any file the user can write; in a direct run with `--workspace` and in the interactive UI, only inside the workspace.
- A Python run with an approval policy, and the interactive UI (bare `melo`, unless `--yolo`), gate every built-in tool whose permission tier is not `read` (`write`, `exec`, `network`); a Python run also gates a provided tool by its tier. Any tool explicitly marked is asked about too. Direct mode, `melo ""` and legacy `/v1` have no policy; console/workspace sessions use `RememberingPolicy`. Output is cut at 50,000 characters.
- Permission tiers: `file_read` is `read`; `file_write` is `write`; `shell_exec` and `python_exec` are `exec`; an MCP tool is `network` with `openWorldHint: true`, else `read` with `readOnlyHint: true` (and not `destructiveHint: true`), else `write` (including no annotations). `require_approval` and `ProvidedTool.requires_approval=True` only add a mark. `Agent.list_tools()` reports each tool's `tier`; `ApprovalRequest.tier` names it in a policy.
- The tool mode decides the default built-ins: `direct`, `python` and `gateway` offer `file_read`, `file_write` and `python_exec` only; `interactive` offers all four. An explicit `builtins` set wins over the default registration, so a named `shell_exec` runs in `direct` and `python` mode whose default omits it; `gateway` refuses it even when named; the checker refuses an unnamed one with `shell_exec is not available in this mode (<mode> mode has no approval policy)` followed by the way to enable it: `Use --builtins all to enable it.` in direct mode, `Name it in AgentOptions(builtins=...) to enable it.` in python mode, and `The gateway does not offer it.` in gateway mode. A call to a built-in the run does not offer returns `<name> is not available in this run. Available tools: …`; an unknown name keeps `Tool not found in registry: <name>`.
- `retrieve` offers the built-ins every step, plus extra (MCP or provided) tools the model has already called and the BM25 top 3 for the task (a tool name in text is not a hint); `all` offers every tool every step. Unoffered calls are refused (`Tool 'NAME' was not offered in this step.`).
- MCP file: `{"mcpServers": {"time": {"command": "uvx", "args": ["mcp-server-time"]}}}` (`servers` also accepted). Optional keys: `env`, `cwd`, `timeout` (120), `startup_timeout` (30), `include_tools`, `require_approval` (`true`, `false` or names), `disabled`.
- Only stdio servers. A server gets the same base env as `shell_exec`/`python_exec` (`PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `TERM`, `LANG`, every `LC_*`, `TMPDIR`) plus its `env` (no `${VAR}` expansion).
- Tool names: `mcp__SERVER__TOOL` (other characters become `_`; over 64 cut with a hash); `config.tools` lists them. Gateway sessions have no MCP tools.

## Memory

- Working memory: the last 20 messages, in RAM. History (task and step records) and long-term memory: RAM unless persisted.
- Persistence: `--memory-dir DIR` or `AgentOptions(memory_dir=DIR)` wins, else `LOCALMELO_PERSIST_MEMORY`. Files: `history.db` always (tasks and steps with their texts redacted: query, result, thought, tool arguments, tool output and error; and in table `llm_calls` every model reply with its redacted reasoning, kind `plan`, `reflect`, `retrieve` or `estimate`, usage and the steps it made; a planning call's `recall_json` holds the recall records it first carried, and `user_version` is 2), `long_term.db` in `legacy` only with an embedding provider and memory on (the explicit reasoning modes create it whenever persistence is on and memory is on), `procedures.db` always (procedural memory: each run's step counts and tool-call labels, added after `run.finished`, a few ms, at most 2 s, skipped after SIGTERM; without persistence it stays in RAM). A directory localmelo creates is `0700`, a new `history.db`, `long_term.db` or `procedures.db` `0600`; an existing file keeps its mode. Export a run's calls: `melo-retrieve --export-run MEMORY_DIR`; procedural memory: `melo-procedures export --memory-dir DIR`.
- Long-term memory needs an embedding backend (setup: `docs/embedding.md`) in `legacy`; the explicit reasoning modes (`compress`, `compress+replay`, `drop`, `replay`) add a text-only store with persistence on and memory on. A new `Agent` or `melo` process recalls earlier runs only through it; history is written but never read back into a run.
- R6-lite's typed store: `long_term.db` `user_version` 1, columns `kind`, `source`, `status`, `admitted_by`, `supersedes`, `links_json`, `provenance_json`, `task_id`, `session_id`, `uses`, `created_at`, `last_used_at`, `embed_model`, `embed_dim`, and table `decisions`. A candidate is written only on `rehearsal`, `user_request` (which also admits the fact a remember request carries after its marker, as `semantic`, or `profile` when first-person), `user_statement`, `outcome` (`--admit-on-outcome on`) or the reserved `sleep`; one of `NEW`, `UPDATE`, `RELATED`, `CONFLICT`, `IGNORE` per decision. Every stored text, provenance included, passes `redact_secrets`; `--keep-decision-text` keeps a decision's text (the hash is always kept). `session_id` is `""` in direct mode.
- Read/score the store without a model: `melo-retrieve --export-store DIR|FILE` (active entries; `text`, `provenance.source_ids`; a directory with no `long_term.db` prints zero and exits 0), `--export-decisions DIR|FILE` (seq order; `text` null unless kept; same empty-directory rule), `--route CANDIDATES.jsonl --memory-dir DIR` (one action line per input; `REFUSED` on a boundary refusal; the scratch directory must be explicit and never the user's). See `docs/retrieval.md`.
- Multi-turn chat: one `Agent` with `record_answers=True` (without it, later runs see earlier queries but not answers), or one gateway `session_id`.
- Sessions: used by the interactive UI (`~/.cache/localmelo/cli/sessions.db`, every turn with its tool calls and output; your messages also in `cli_history`); Python API experimental (`~/.cache/localmelo/gateway/` by default otherwise). Plain text, files `0600`.
- Delete memory with the Python API: `await agent.hippo.forget(task_id)` removes the task's `tasks`, `steps` and `llm_calls` rows, its typed long entries and its decisions; `forget_all()` removes both stores, step summaries included. No command yet. Sessions (`~/.cache/localmelo/cli/sessions.db`, `~/.cache/localmelo/gateway/sessions.db`), procedures and the web workspace's files (`~/.cache/localmelo/playground/`) go only by deleting them with localmelo stopped. Not encrypted. One gateway's sessions share one set of files.

## Gotchas

- Exit 1 and exit 2 can come with no JSON line (setup or usage error, message on stderr). Check that stdout is non-empty before parsing, then read `status`.
- Always set `--timeout` (or `timeout_s`): the request timeout counts per read, so a server that keeps sending bytes never trips it, and a silent server costs about 3 x the request timeout + 5 s per request (two retries).
- `--serve` silently ignores a positional task; direct mode silently ignores `--host`, `--port`, `--reconfigure`.
- A `session_id` that is not a string, or that does not match `^[a-zA-Z0-9_-]{1,64}$`, gets the 400 `Invalid session_id format`; omit it or send `null` for a new session.
- One `Agent` per concurrent task: `run_task` has no overlap guard (runs share working memory and counters).
- `ollama` backend: `result` can start with a `<think>...</think>` block.
- Gateway: `python_exec` runs in a child process, so the gateway keeps answering while the code runs, and Stop kills it. `DELETE` on a session running a task: 409 `{"error", "session_id"}`, and the run goes on; `/v1/agent` has no cancel route (the web workspace's cancel is for its own chats). At shutdown every session is closed, a busy one included, and a task still running then ends as `crashed`.
- Stopping: `&` jobs from a non-interactive shell ignore SIGINT; send SIGTERM. Direct mode exits 143 within 8 s. The gateway waits up to 3 seconds for runs in flight, cancels a longer one (its client gets a 500 and the run ends `crashed`), and exits 143.
- Under `uv run`, `$!` is uv: SIGTERM reaches melo, SIGKILL does not (the gateway keeps listening). In scripts start `.venv/bin/melo`, or SIGKILL the child (`pkill -KILL -f 'melo --serve --port PORT'`).
- `--daemon install` takes `--port` but not `--host`, gets no shell env vars (no cloud keys), and its KeepAlive restarts a killed gateway: use `--daemon uninstall`.

## Status of features

- Available: direct mode, the gateway, the interactive UI (bare `melo` in a terminal, with first-run setup, live tool blocks, thinking excerpts, notices, diffs, approvals, `/model`, `/backend`, `-c`/`-r`, `/sessions`, `/resume`, `/title`, `/undo`, `/usage`, `/memory`, `/copy`, MCP servers from `--mcp-config` or `mcp_config`), the `melo ""` loop, MCP stdio servers (the interactive UI, direct mode, the Python API), the macOS background service, and the gateway console's session store (`gateway/sessions.db`), which API v2 runs and reads.
- Experimental: the Python API. Offline only (runs do not use them): `melo-retrieve` and its `bm25`, `llm`, `embedding` retrievers; `melo-procedures` (`episodes`, `replay`, `export`, `forget`: replays the progress rules on recorded runs; every run itself writes procedural memory at its end). The scheduler core in `support/scheduler/` gates the gateway's web-workspace chats and a console session's turns; direct runs and the interactive CLI do not read it. Sessions (`support/sessions/`): used by the interactive UI (`cli/sessions.db`) and the gateway console (`gateway/sessions.db`, writer `gateway`), and by the experimental Python API; direct mode and the legacy `/v1/agent/run` do not use them.
- Planned, not on main: the interactive UI's attachment sending and `!` shell mode; more workspace controls; several tasks on one model server, the user's conversation first; a percent bar, off until repeated runs pass the replay.

## Working on the code

- The directory that holds `pyproject.toml` IS the package `localmelo` (`package-dir`: `localmelo = "."`): `melo/agent/agent.py` imports as `localmelo.melo.agent.agent`. Keep the clone named `localmelo`; never create `localmelo/localmelo/`.
- `melo/` is the core (run loop, checks, executor, memory, contracts); `support/` holds backends, providers, gateway, MCP, config, wizard, `melo-retrieve`, `melo-procedures`, scheduler. `melo/` does not import `support/` (exceptions: `tests/test_layering.py`).
- Setup: `uv sync --extra dev --extra gateway`. Tests while working: `uv run pytest --testmon -q` (after its first run, only tests that cover the changed files run). Before a pull request: `uv run pytest -n auto -q` (the offline suite in parallel). A plain run opens no socket: `tests/smoke/test_backend_smoke.py` is skipped unless `LOCALMELO_SMOKE=1`, and `--ignore=tests/smoke/test_backend_smoke.py` still works; pre-commit hooks run it too.
- Lint: `uv run ruff check .`, `uv run black --check .`, `uv run mypy .`. Web workspace JS (Node from `.nvmrc`): `node --test tests/gateway/*.mjs`.
- Commits `[Area] Imperative summary`; PR titles add the type (`[Feature][Agent] ...`). Tests and docs (with `README.zh-CN.md`, `docs/zh-CN/`) in the same PR, in English ([CONTRIBUTING.md](https://github.com/localmelo/localmelo/blob/main/CONTRIBUTING.md)). The full developer guide is the website's [developers page](https://localmelo.github.io/localmelo/en/developers.html): the repository layout, setup, tests, adding a backend, a built-in tool or a check, commits and pull requests, and the docs and website layout.
