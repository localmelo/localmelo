Pre-alpha local-first agent runtime

Run an agent loop with explicit memory, tool use, and local backend control.

localmelo separates the core agent runtime from infrastructure. It connects to user-managed local or cloud model endpoints, records task history, and keeps memory boundaries visible instead of hiding them behind a single context blob.

Project state

What is stable today versus still experimental.

Stable enough to verify

Online core loop

Direct CLI mode, gateway entry points, provider registry, tool execution, and checker boundaries have automated coverage.

Experimental

Memory persistence

SQLite-backed history and long-term memory are async and persistent, but retrieval and promotion policies are still being shaped.

Planned

Sleep pipeline

Sleep-time training and evaluation are scaffolded. The real personalization workflow is a later track, not part of the current runtime baseline.

Runtime model

The core split is simple: `melo/` owns behavior, `support/` owns infrastructure.

Agent plans and decides

The agent retrieves context, resolves tools, asks the model for the next step, and either returns a final answer or executes a tool call.

Checker validates boundaries

Gateway ingress, planning payloads, executor calls, output size, and memory writes flow through explicit checks.

Memory stays layered

Working memory, history, long-term retrieval, and tool registry are separate surfaces with separate responsibilities.

Backends stay external

localmelo connects to configured endpoints. It does not start or manage Ollama, MLC, vLLM, SGLang, or cloud runtime infrastructure.
